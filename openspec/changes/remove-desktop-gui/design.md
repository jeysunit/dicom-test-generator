# Design

## Context

削除の理由は proposal.md の Why のとおり。`app/gui/` を import しているのは
`app/gui/` と `tests/gui/` の中だけで、ほかのモジュールからは使われていない。
ADR-0011 の案 B は「PySide6 の画面でできる作成が Web 画面でもできたら削除する」
という条件だったが、Web 画面でできるのは撮影だけで、Job YAML や `quick` に相当する
作成の画面は無い。

## Goals / Non-Goals

**Goals:**

- デスクトップ画面と、それだけが使う依存・CI の設定・ドキュメントを削除する
- 削除の判断と、ADR-0011 の削除の条件を置き換えたことを ADR に残す

**Non-Goals:**

- Web 画面にファイルの作成の画面を追加すること（roadmap の未実装に書く）
- CLI の動作の変更

## Decisions

1. **削除の条件を「CLI で作成できること」に置き換える。** ADR-0011 の案 B の条件
   （Web 画面でも同じ作成ができること）は待たない。ファイルの作成は CLI の
   `generate`・`quick` でできており、デスクトップ画面でだけできることは無い。
   採用しなかった案：Web 画面に作成の画面を作ってから削除する（画面を作るまで
   PySide6 と Qt の CI の設定を保守し続けることになる）
2. **新しい ADR-0022 を作成し、ADR-0003・ADR-0006 を置き換え済みにする。**
   ADR-0006 は GUI の非同期処理（QThread）だけを決めた ADR なので、画面と一緒に
   役目を終える。ADR-0011 は採用のまま、状態の行に「既存の PySide6 の GUI の扱い」を
   ADR-0022 が置き換えたことを書く（本文は変えない）
3. **`docs/spec/05_gui.md` はファイル名を変えずに欠番の文書にする。** ほかの欠番は
   `NN_unused.md` だが、ADR-0006・ADR-0011 の本文が `05_gui.md` へリンクしており、
   採用した ADR の本文は書き換えないので、リンクが切れないようにファイル名を残す
4. **Dockerfile の依存の除外は、残る行（pytest・httpx）だけにする。** PySide6 と
   pytest-qt は `requirements.txt` から無くなるので、除外の正規表現からも削除する
5. **CI の Docker のジョブの「PySide6 が無い」確認は削除する。** 依存に PySide6 が
   無くなり、確認する意味が無くなるため。CLI が root 以外の利用者で動く確認は残す

## Risks / Trade-offs

- [`python -m app.gui` を使っている利用者がいる] → README・usage に CLI での作成の
  手順がある。PR の本文に、削除したことと代わりのコマンドを書く
- [ADR-0006・ADR-0011 の本文の `05_gui.md` へのリンク先が欠番の文書になる] →
  欠番の文書に、削除したことと ADR-0022 へのリンクを書く
