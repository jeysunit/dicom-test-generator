# Proposal

## Why

撮影の画面の「シリーズ数」と「画像数」は、利用者が毎回手で入れる。作る画像は
どのシリーズも CT の軸位の画像（Image Type `ORIGINAL\PRIMARY\AXIAL`）で、
Series Description を持たない。実際の CT の検査では、位置決めの画像、軸位の
再構成、冠状断・矢状断の画像、線量の画面が、部位ごとに決まった並びで PACS に
送られる。PACS の表示の決まり（シリーズの並べ方・位置決めの扱い）や線量の
集計を試すには、この並びに近い検査が要る。

公開の資料（design.md の「調べたこと」と「出典」）から、次のことが分かった。

- CT：1シリーズ目は位置決めの画像で、1〜2 枚。頭部は側面の 1 枚（正面は任意）、
  胸部は正面の 1 枚の例が多い（AAPM のプロトコル集）。最後のシリーズは線量の
  画面（CTDI と DLP の一覧を写した Secondary Capture の画像）が多く、画面 1 つで
  1 枚が基本。長い検査では画面ごとに 2 枚以上になる。GE は線量の画面をシリーズ
  999、線量の SR（RDSR。画像ではない）をシリーズ 997 にするので、最後に2つの
  シリーズが並ぶ
- MR：1シリーズ目はローカライザーで、3面を1シリーズに入れ、1面に 5〜8 枚の
  例がある。最後に線量の画面は無い
- CT・MR とも、中間のシリーズは部位・目的ごとに決まる（プロトコル集は部位ごとに
  シリーズの名前を並べる）。中間の断面のシリーズの画像数を載せた公開の資料は、
  CT では無く、MR は Canon の頭部の例（2D は各 25 枚）だけだった
- CR・DX は部位ごとに撮影の方向が決まり（胸部は PA と側面、など）、1方向が1枚。
  US は記録する断面の数で決まる（腹部は判定マニュアルが 16 断面以上を勧める）

承認者の見立て（1シリーズ目は 1 枚、最終シリーズは 2 枚が多い、中間は部位で
決まる）は、CT では1シリーズ目と中間が資料と合う。最終シリーズは線量の画面だけ
なら 1 枚が基本で、2 に見えるのは線量の画面が2つに分かれるか、RDSR が並ぶとき。
MR では中間だけが合い、1シリーズ目のローカライザーは複数の枚数になる。

テストデータの作成が目的なので、利用者が画像数を考えなくてよいことを優先する。
ルーチンは、中間のシリーズも含めて、すべてのシリーズに既定の画像数を持つ。
中間のシリーズの画像数は、資料のスライス厚と想定した撮影範囲から計算する（式と
範囲は design.md の「既定の画像数の決め方」）。

## What Changes

- 撮影は、既定でルーチンの並びと画像数で行う。撮影の画面を開くと、予約の検査の
  記述（Requested Procedure Description・Scheduled Procedure Step Description）と
  部位（Body Part Examined があれば）を、ルーチンの YAML に書いた見出しの言葉
  （頭部・胸部・腹部・CTA・ダイナミックなど）と照らして当てたルーチンが、最初から
  選ばれている。利用者が何も選ばずに「撮影」を押せば、そのルーチンで撮れる。当たら
  なければ、そのモダリティの既定のルーチン（CT は胸部）。緊急の患者（予約なし）は、
  テンプレートのモダリティの既定のルーチン
- 撮影の設定に「ルーチン」の選択を足す。変えたい人だけが別のルーチンに変え、画像数も
  手で変えられる。今の「シリーズ数」と「画像数」の手入力は、選択肢の最後の「手で
  入れる」として残す
- ルーチンは `templates/routine/` の YAML に置き、DTG が扱うモダリティ（CT・MR・
  CR・DX・US）のルーチンを付ける。CT は頭部・胸部・胸腹部骨盤・腹部骨盤・肝臓の
  ダイナミック・冠動脈 CTA・腰椎、MR は頭部・腰椎・膝・肩、CR と DX は胸部・腹部・
  腰椎・頸椎・膝・手、US は腹部。施設のルーチンは同じ形の YAML を足して作る
- ルーチンの形はモダリティごとに変える。CT はシリーズの種類（位置決め・軸位・
  冠状断・矢状断・線量の画面）と再構成、MR はシーケンス、CR・DX は撮影の方向、
  US は静止画と動画の数を持つ。どのルーチンも、すべてのシリーズに既定の画像数を
  持つ
- CT のシリーズの種類に合わせて DICOM の値を変える（Image Type・Image Orientation
  (Patient)・SOP Class・Series Description・Protocol Name・造影の有無）。詳しくは
  design.md
- CLI の `exam` も同じ決まりで、`-s`・`-i`・`--routine` を省けば予約に合うルーチンで
  撮る。`--routine 名前` で選べ、`-s`・`-i` を指定すれば今の手入力と同じになる

## 承認者が決めること

1. 作る画像の範囲。（推奨）CT は、位置決め・軸位・冠状断・矢状断・線量の画面まで
   作る。線量の画面は Secondary Capture で作り、RDSR（線量の SR。画像ではない）は
   入れない。MR・CR・DX・US は、この change でルーチンと選び方までを入れ、画像を
   作る処理は roadmap の「CT 以外のモダリティ」の change で入れる（DTG が今作れる
   SOP Class は CT Image Storage だけで、MR の画像を作る処理は別の大きさの仕事に
   なる）。それまで MR などの予約は、今と同じく「予約は MR、テンプレートは CT
   です」で止まる
2. 線量の画面のシリーズ番号。（推奨）ルーチンの YAML に書けるようにし、付ける
   ルーチンは続きの番号（最後）にする。999・501 のような番号は施設のルーチンで
   書く。追加撮影（同じ Study にシリーズを足す）で番号がぶつからないよう、
   予約ごとに使った番号を記録し、書いた番号が既にあれば撮影せずに止める。自動の
   番号は、自動で付けた番号の続きにし、書いた番号を飛ばす
3. ルーチンの選び方。（推奨）予約の検査の記述（Requested Procedure Description・
   Scheduled Procedure Step Description）と部位（Body Part Examined があれば）を、
   ルーチンの YAML に書いた見出しの言葉と照らして自動で当てる。当たらなければ、
   そのモダリティの既定のルーチン（CT は胸部）にする。施設の検査のコードの対応表は
   持たない。緊急の患者（予約なし）は、モダリティの既定のルーチン。画面では当たった
   ルーチンを最初から選んだ状態で出し、変えたい人だけが変える。代わりの案：画面で
   利用者がルーチンを選ぶだけにする（当て方の作りは要らないが、撮影のたびに選ぶ
   手間がかかる）

## Capabilities

### New Capabilities

- `exam-routines`: 撮影のルーチン（部位ごとのシリーズの並び）と、シリーズの種類ごとの DICOM の値

### Modified Capabilities

（なし）

## Impact

- core：`app/core/models.py`（シリーズの種類）、`app/core/generator.py`（種類ごとの
  Image Type・向き）、線量の画面の Secondary Capture を作る処理（新しい）
- サービス：`app/services/`（ルーチンの読み込み）、`app/modality/service.py`
  （`ExamRequest` にルーチン）
- 画面：撮影の画面の「ルーチン」とシリーズの行。CLI：`exam --routine`
- テンプレート：`templates/routine/`（新しい）
- spec：02・03・06、12 の 5.2（MWL の返却を求める値に Body Part Examined）、12a の
  10.5・12a の CLI。ADR（シリーズの種類と線量の画面の
  作り方、ルーチンの当て方）
- 既定の撮影が変わる：今は `-s`・`-i` を省くと1シリーズ1枚だが、ルーチンの並びと
  枚数になる。`-s`・`-i` を省いて枚数を前提にしている試験は、`-s 1` を指定するか
  「手で入れる」に直す
- 「手で入れる」を選んだ撮影の画像は、今と変わらない
