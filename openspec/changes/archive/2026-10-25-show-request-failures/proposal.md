# Proposal

## Why

ワークリスト取得と C-ECHO の通信失敗が画面に出ず、401 の応答が生の文字列で
表示される（#34・#38）。PACS の送信失敗の理由は英語で、長いと表が広がる。
再送で失敗が残っても成功色になり（#48）、キューを読めない場合も空の履歴と
表示される（#50）。

## What Changes

- 通信失敗と 401 の表示先を共通化し、各操作の結果に知らせる
- 送信失敗の理由を日本語で示し、表では1行で切り、全文と原文は詳細に出す
- 再送後に失敗が残る場合はエラーの知らせにする
- キューを読めない場合は空の履歴の文言を出さない

## Capabilities

### New Capabilities

（なし）

### Modified Capabilities

- `user-interfaces`: 通信失敗と認証切れの表示先と文言
- `worklist-screen`: 取得と取得し直しの失敗の知らせ
- `image-sending`: 失敗の理由、再送の結果、キューの読み込み失敗

## Impact

- 画面：`app.js`・送信キューのテンプレート・表示用の関数・PACS のルート・CSS
- 文書：spec 12a の 10.6・10.8 と OpenSpec
- 試験：`tests/web/` の表示と静的ファイルの確認
- DICOM の通信と CLI の動作は変えない
