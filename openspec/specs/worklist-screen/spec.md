# worklist-screen Specification

## Purpose

Web 画面のワークリストで、予約を取得し、選び、選んだ予約を取得し直す操作と、
失敗したときに利用者へ出す知らせを定める。

## Requirements

### Requirement: 「取得し直す」は選んだ予約だけを取得し直す

「取得し直す」は、一覧で選んだ予約を、その受付番号と Requested Procedure ID を
条件にした C-FIND（PS3.4 K.6.1、IHE RAD TF-2 4.5）で取得し直し、一覧のその行を
最新の値にしなければならない（SHALL）。予約を選んでいない間は、ボタンを押せない
ようにしなければならない（SHALL）。

#### Scenario: 行を選んで取得し直す

- **WHEN** 利用者がワークリストを取得し、受付番号 `A0001` の行を選んで「取得し直す」を押す
- **THEN** 受付番号 `A0001` と、その予約の Requested Procedure ID を条件にした C-FIND が送られ、一覧のその行が応答の値になり、「取得し直しました」と表示される

#### Scenario: 行を選ぶまでボタンを押せない

- **WHEN** 利用者が「ワークリストを取得」を押した直後で、どの行も選んでいない
- **THEN** 「取得し直す」は押せない状態で表示され、行を1つ選ぶと押せるようになる

#### Scenario: 予約の鍵の無い要求が届く

- **WHEN** 予約を選ばないまま「取得し直す」の要求がサーバーに届く（スクリプトが無効のときなど）
- **THEN** C-FIND は送られず、「予約を選んでから「取得し直す」を押してください」と表示され、一覧はそのまま残る

### Requirement: 取得し直せないときは利用者向けの日本語で知らせる

ワークリストの画面と撮影の画面は、予約を取得し直せない・見つからないとき、原因と
次の操作を日本語で表示しなければならない（SHALL）。知らせには、内部の予約の鍵と
CLI 向けの hint を含めてはならない（SHALL NOT）。

#### Scenario: 最後の一覧に無い予約

- **WHEN** 最後に取得した一覧に無い予約を、取得し直す・撮影の画面で開こうとする
- **THEN** 「この予約は最後に取得した一覧にありません。「ワークリストを取得」からやり直してください」と表示され、`worklist_key` と `worklist query` の文字列は表示されない

#### Scenario: RIS から予約が無くなっている

- **WHEN** 選んだ予約（受付番号 `A0001`）を取得し直したら、応答にその予約が無い
- **THEN** 「この予約はワークリストにもうありません（受付番号 A0001）。RIS で取り消されたか、変更された可能性があります」と表示され、一覧の行は消さずに残る

#### Scenario: 取得し直す途中で時間切れになる

- **WHEN** 取得し直す C-FIND が、設定の時間（30 秒）を過ぎても終わらない
- **THEN** 「取得し直す途中で時間切れになりました（30 秒）。もう一度押してください」と表示され、一覧の行は前の値のまま残る
