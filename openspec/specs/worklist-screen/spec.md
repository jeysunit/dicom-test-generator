# worklist-screen Specification

## Purpose

Web 画面のワークリストで、予約を取得し、選び、選んだ予約を再検索する操作と、
失敗したときに利用者へ出す知らせを定める。

## Requirements

### Requirement: 取得の通信失敗と認証切れを一覧の場所に出す

ワークリストの取得と「再検索」が通信で失敗したときは、一覧の場所
（`#results`）にエラーの知らせを出さなければならない（SHALL）。401 の場合も
同じ場所にログインの知らせを出し、生の応答では差し替えない。

#### Scenario: ワークリストの取得が届かない

- **WHEN** 「ワークリスト検索」の通信が失敗する
- **THEN** 一覧の場所に接続を確かめてもう一度押すよう知らせる

#### Scenario: 再検索する要求の認証が切れる

- **WHEN** 「再検索」の応答が 401 になる
- **THEN** 一覧の場所にページを読み込み直してログインし直すよう知らせる

### Requirement: 「再検索」は選んだ予約だけを再検索する

「再検索」は、一覧で選んだ予約を、その受付番号と Requested Procedure ID を
条件にした C-FIND（PS3.4 K.6.1、IHE RAD TF-2 4.5）で再検索し、一覧のその行を
最新の値にしなければならない（SHALL）。予約を選んでいない間は、ボタンを押せない
ようにしなければならない（SHALL）。

#### Scenario: 行を選んで再検索する

- **WHEN** 利用者がワークリストを検索し、受付番号 `A0001` の行を選んで「再検索」を押す
- **THEN** 受付番号 `A0001` と、その予約の Requested Procedure ID を条件にした C-FIND が送られ、一覧のその行が応答の値になり、「再検索しました」と表示される

#### Scenario: 開いている詳細も新しい値になる

- **WHEN** 受付番号 `A0001` の行を選んで詳細のパネルを開き、RIS の側で検査名が変わった後に「再検索」を押す
- **THEN** 一覧の行と一緒に、詳細のパネルも新しい検査名になる

#### Scenario: 行を選ぶまでボタンを押せない

- **WHEN** 利用者が「ワークリスト検索」を押した直後で、どの行も選んでいない
- **THEN** 「再検索」は押せない状態で表示され、行を1つ選ぶと押せるようになる

#### Scenario: 予約の鍵の無い要求が届く

- **WHEN** 予約を選ばないまま「再検索」の要求がサーバーに届く（スクリプトが無効のときなど）
- **THEN** C-FIND は送られず、「予約を選んでから「再検索」を押してください」と表示され、一覧はそのまま残る

### Requirement: 再検索できないときは利用者向けの日本語で知らせる

ワークリストの画面と撮影の画面は、予約を再検索できない・見つからないとき、原因と
次の操作を日本語で表示しなければならない（SHALL）。知らせには、内部の予約の鍵と
CLI 向けの hint を含めてはならない（SHALL NOT）。

#### Scenario: 最後の一覧に無い予約

- **WHEN** 最後に取得した一覧に無い予約を、再検索・撮影の画面で開こうとする
- **THEN** 「この予約は最後に取得した一覧にありません。「ワークリスト検索」からやり直してください」と表示され、`worklist_key` と `worklist query` の文字列は表示されない

#### Scenario: RIS から予約が無くなっている

- **WHEN** 選んだ予約（受付番号 `A0001`）を再検索したら、応答にその予約が無い
- **THEN** 「この予約はワークリストにもうありません（受付番号 A0001）。RIS で取り消されたか、変更された可能性があります」と表示され、一覧の行は消さずに残る

#### Scenario: 再検索の途中で時間切れになる

- **WHEN** 再検索する C-FIND が、設定の時間（30 秒）を過ぎても終わらない
- **THEN** 「再検索の途中で時間切れになりました（30 秒）。もう一度押してください」と表示され、一覧の行は前の値のまま残る

### Requirement: 装置の AEタイトルの絞り込みをそれと分かる言葉で示す

ワークリストの画面は、Scheduled Station AE Title (0040,0001) の検索条件を
「装置の AEタイトル」というラベルと、「この装置で絞る（<自分の AEタイトル>）」
「絞らない」の選択肢で表示しなければならない（SHALL）。選択肢は、幅の狭い画面でも
括弧の AEタイトルまで見える長さにする。初期設定は「この装置で絞る」とし、選ぶと Scheduled Procedure Step Sequence の
中の (0040,0001) に自分の AEタイトルを入れて送る（PS3.4 K.6.1.2.2、IHE RAD TF-2
Table 4.5-2）。

#### Scenario: 初期設定の条件で取得する

- **WHEN** 自分の AEタイトルが `DTG_CT01` の画面で、ワークリストの画面を開いて「ワークリスト検索」を押す
- **THEN** 条件の欄に「装置の AEタイトル」「この装置で絞る（DTG_CT01）」と表示され、C-FIND の Scheduled Procedure Step Sequence の (0040,0001) に `DTG_CT01` が入る

#### Scenario: 絞らないで取得する

- **WHEN** 利用者が「絞らない」を選んで「ワークリスト検索」を押す
- **THEN** C-FIND の (0040,0001) は長さ 0 で送られ（全ての値に一致）、別の装置の予約には「別の装置」の印が付く

### Requirement: 予約の詳細に予定の装置の AEタイトルを分けて示す

予約の詳細のパネルは、予約の Scheduled Station AE Title (0040,0001) を「予定の
装置の AEタイトル」の行に、予定日時・モダリティとは別に表示しなければならない
（SHALL）。値が空なら「—」を表示する。

#### Scenario: 詳細を開く

- **WHEN** 利用者が (0040,0001) が `DTG_MR01` の予約の行を選ぶ
- **THEN** 詳細のパネルに「予定の装置の AEタイトル」の行があり、値は `DTG_MR01` で、「予定」の行には予定日時とモダリティだけが表示される

### Requirement: 予約の詳細に依頼医と紹介医を分けて示す

予約の詳細のパネルは、患者の氏名を「氏名」、Requesting Physician (0032,1032)（PS3.3 C.4.12）を
「依頼医」、Referring Physician's Name (0008,0090)（PS3.3 C.7.2.1）を「紹介医」として、
別の行に表示しなければならない（SHALL）。3 つとも、成分の区切り `^` と成分グループの
区切り `=` を出さず、一覧の氏名と同じ順（漢字・かな・英字）に ` / ` で区切る。値が
空なら「—」を表示する。

#### Scenario: 両方の値がある予約

- **WHEN** (0032,1032) が `Sato^Ichiro`、(0008,0090) が `Suzuki^Hanako` の予約の行を選ぶ
- **THEN** 詳細のパネルに「依頼医 Sato Ichiro」と「紹介医 Suzuki Hanako」が表示される

#### Scenario: 依頼医が空の予約

- **WHEN** (0032,1032) が空か応答に無い予約の行を選ぶ
- **THEN** 「依頼医」の行に「—」が表示される

#### Scenario: 漢字・かな・英字がそろった氏名

- **WHEN** 氏名が `YAMADA^TARO=山田^太郎=やまだ^たろう` の予約の行を選ぶ
- **THEN** 詳細のパネルの「氏名」は「山田 太郎 / やまだ たろう / YAMADA TARO」で、`^` と `=` は出ない

### Requirement: 取得の時刻に UTC の差を添える

ワークリストの一覧の取得の時刻は、画面を動かすマシンの時刻に、UTC からの差を添えて
「（2026-10-23 08:03:44 UTC+09:00 に取得）」の形で出さなければならない（SHALL）。

#### Scenario: 一覧を取得する

- **WHEN** 「ワークリスト検索」を押して一覧が出る
- **THEN** 一覧の下に「12 件（2026-10-23 08:03:44 UTC+09:00 に取得）」の形で時刻と UTC の差が出る
