# image-sending Specification

## Purpose

撮影した画像を PACS へ送る操作（C-STORE。PS3.4 Annex B）と、送信キュー・再送・
その表示を定める。

## Requirements

### Requirement: 送信失敗の理由を日本語で示す

PACS の送信失敗の理由は、原因と確かめる場所を日本語で示さなければならない
（SHALL）。接続不能は送り先の電源とポート、接続拒否は AE タイトルの登録、
送信中の切断は接続、応答なしは稼働状況、画像の拒否は状態の値と送り先の記録、
読めないファイルは元のファイルを示す。既存の日本語はそのまま表示し、未知の理由は
「送信に失敗しました」とする。表の理由は幅を制限して1行で切り、詳細の枠の
「失敗の理由」に全文と等幅の原文を出す。

#### Scenario: 接続できない

- **WHEN** 送信先 PACS_TEST の 127.0.0.1:18200 に接続できない
- **THEN** 理由は「接続できませんでした（PACS_TEST・127.0.0.1:18200）。送り先の電源とポートを確かめてください」になり、原文は詳細の枠だけに出る

#### Scenario: 長い理由

- **WHEN** 送信失敗の理由が長い
- **THEN** 表の列は理由の長さで広がらず、全文は詳細で読める

### Requirement: 再送で失敗が残るときはエラーで知らせる

再送後に失敗が残る場合は、送信完了と送信失敗の件数を添えて、まだ送信できていないことを
エラーの知らせ（`notice-error`・`role="alert"`）で示さなければならない（SHALL）。
送信完了の件の再送も、新しい件が送信失敗ならエラーにする。全部送信完了のときの
文言は変えない。知らせは再取得で消さない。

#### Scenario: 1 件の失敗が残る

- **WHEN** 1 件を再送したが、送信失敗になる
- **THEN** 「1 件を再送しましたが、まだ送信できていません（送信完了 0 件・送信失敗 1 件）」をエラーで出す

#### Scenario: 送信完了の件を再送して失敗する

- **WHEN** 送信完了の件をジョブ 2 として再送し、送信失敗になる
- **THEN** 「ジョブ 2 として再送しました（送信失敗）」をエラーで出す

### Requirement: キューを読めない場合は空の履歴として表示しない

送信キューを読めないときはエラーの知らせだけを出し、「送信した検査はまだありません」
を出してはならない（SHALL NOT）。

#### Scenario: キューの読み込みに失敗する

- **WHEN** PACS の画面で送信キューを読めない
- **THEN** エラーが出て、空の履歴の文言は出ない

### Requirement: 送信キューの表に画像の受付番号を示す

送信キューの件は、送るフォルダの画像の Accession Number (0008,0050) を受付番号
として持ち、PACS の画面の送信キューの表に表示しなければならない（SHALL）。画面から
の送信と CLI の `send` の両方に効く。画像の受付番号が空なら「—」を表示する。

#### Scenario: 予約で撮って送る

- **WHEN** 受付番号 `A0001` の予約で「撮影して送信」を押す
- **THEN** PACS の画面の送信キューの表の、その件の受付番号の欄に `A0001` が表示される

#### Scenario: CLI で送る

- **WHEN** 受付番号 `A0002` の画像のフォルダを `python -m app.cli send <フォルダ>` で送る
- **THEN** `queue list` の出力と PACS の画面の、その件の受付番号が `A0002` になる

#### Scenario: 緊急の患者

- **WHEN** 緊急の患者（受付番号は空）で撮影して送る
- **THEN** その件の受付番号の欄に「—」が表示される

#### Scenario: この変更の前に作った件

- **WHEN** 受付番号が空のまま記録された件があり、そのフォルダの画像の受付番号が `A0003` である
- **THEN** PACS の画面の受付番号の欄に `A0003` が表示される

### Requirement: 送信を終えた件は何回でも送り直せる

DTG は、送信完了の件を、回数の上限なしに送り直せなければならない（SHALL）。
送信完了の件の送り直しは、同じフォルダの画像をすべて、その件と同じ送信先へ、
新しい送信キューの件として送る。送信中の件は送り直せない。

#### Scenario: 送信完了の件を送り直す

- **WHEN** PACS の画面で、送信完了の件（画像 3 枚）の「再送」を押す
- **THEN** 同じ送信先へ画像 3 枚を送る新しい件ができ、元の件は送信完了のまま残る

#### Scenario: 何回でも送り直す

- **WHEN** 同じ件の「再送」を 3 回続けて押し、そのたびに送信が終わる
- **THEN** 3 回とも送り直しが受け付けられ、新しい件が 3 つできる

#### Scenario: 送信中の件

- **WHEN** 送信中の件がある
- **THEN** その件には「再送」が表示されず、その件の送り直しの要求は断られる

### Requirement: 送信失敗の件の再送は送れていない画像だけを送る

DTG は、送信失敗の件の再送で、その件の送れていない画像だけを、同じ件のまま
送らなければならない（SHALL）。

#### Scenario: 一部だけ送れなかった件

- **WHEN** 画像 3 枚のうち 1 枚が送れずに送信失敗になった件の「再送」を押す
- **THEN** 送れなかった 1 枚だけが送られ、送れればその件が送信完了になる

### Requirement: 送り直しでは画像を作り直さない

DTG は、送り直しで、撮影のときに書き出したファイルをそのまま送らなければならない
（SHALL）。SOP Instance UID・Series Instance UID・Study Instance UID は、最初の
送信と同じになる（PS3.5 9 の UID は1つの物を指す）。

#### Scenario: 送り直した画像の UID

- **WHEN** 送信完了の件を送り直す
- **THEN** 送られた画像の SOP Instance UID は、最初の送信の画像の SOP Instance UID と同じになる

### Requirement: 撮影の画面から続けて送り直せる

撮影の画面は、送信の結果を表示した後も、「もう一度送信」で同じ画像を送り直せ
なければならない（SHALL）。押したら、応答が返るまでボタンを押せなくする。

#### Scenario: 撮影して送った後に送り直す

- **WHEN** 「撮影して送信」の結果が表示された後に「もう一度送信」を押す
- **THEN** 同じフォルダの画像が既定の送信先へ新しい件として送られ、その結果が表示され、「もう一度送信」はまた押せる

### Requirement: 送信ジョブの詳細を開いても表の形を変えない

PACS の画面は、送信ジョブの表の「詳細」を押したとき、元のファイル・試行回数・
名乗る AE タイトルを、表のセルの外に浮かぶ枠に出さなければならない（SHALL）。
詳細を開いても、表の各列の幅と各行の高さは変わらない。同時に開く枠は1つで、
枠の外を押すか Esc で閉じる。

#### Scenario: 1つの行の詳細を開く

- **WHEN** 送信ジョブが 4 件ある表で、ジョブ 3 の「詳細」を押す
- **THEN** ジョブ 3 の元のファイル・試行回数・名乗る AE タイトルが枠に出て、表の各列の幅と各行の高さは押す前と同じになる

#### Scenario: 別の行の詳細を開く

- **WHEN** ジョブ 3 の枠を開いたまま、ジョブ 1 の「詳細」を押す
- **THEN** ジョブ 3 の枠は閉じ、ジョブ 1 の枠だけが開く

### Requirement: 再取得の後も開いた詳細を開いたままにする

PACS の画面は、2 秒ごとの再取得で送信ジョブの表を差し替えたとき、開いていた
詳細の枠を開いたままにし、中身を新しい値にしなければならない（SHALL）。差し替えの
間に、枠が閉じた状態を描かない。再送を押してから応答が返るまで再取得を止める
動きは変えない。

#### Scenario: 開いたまま再取得する

- **WHEN** ジョブ 3 の枠を開き、再取得でジョブ 3 の試行回数が 1 から 2 になる
- **THEN** 枠は開いたままで、試行回数は 2 になる

#### Scenario: 再送の応答を待つ間

- **WHEN** ジョブ 3 の「再送」を押し、応答が返る前にジョブ 1 の「詳細」を押す
- **THEN** 応答が返るまで表は差し替わらず、応答で表が差し替わった後も、ジョブ 1 の枠は開いたまま残る

### Requirement: 再取得の後も表の横スクロールの位置を保つ

PACS の画面は、2 秒ごとの再取得や再送の応答で送信ジョブの表を差し替えても、狭い画面で
表を横にスクロールしている位置を保たなければならない（SHALL）。

#### Scenario: 狭い画面で表を横にスクロールする

- **WHEN** 幅 390px の画面で表を右へスクロールし、再取得を待つ
- **THEN** 差し替えの後も、同じ位置までスクロールしたまま表が出る

### Requirement: 送信キューの時刻の見出しに UTC の差を添える

PACS の画面の送信ジョブの表は、検査日時・受付日時・完了日時の見出しに、画面を動かす
マシンの時刻の UTC からの差（`UTC+09:00` の形）を添えなければならない（SHALL）。

#### Scenario: 時刻の見出し

- **WHEN** PACS の画面を開く
- **THEN** 3 つの時刻の見出しに `UTC+09:00` のような差が出る

### Requirement: 再送の応答を待つ間はすべての再送のボタンを押せなくする

PACS の画面は、「再送」か「失敗をすべて再送」を押してから応答が返るまでの間、表の中の
すべての「再送」と「失敗をすべて再送」を押せなくしなければならない（SHALL）。応答が
返ったら押せる形に戻す。サーバーが再送を断ったときは、表を残して理由を表の上の知らせの
場所に出す。

#### Scenario: 再送の応答を待つ間に別のボタンを押す

- **WHEN** ジョブ 2 の「再送」を押し、応答が返る前に、ジョブ 1 の「再送」と「失敗をすべて再送」を押そうとする
- **THEN** どちらも押せず、応答が返った後は押せる

#### Scenario: サーバーが再送を断る

- **WHEN** 「失敗をすべて再送」を押し、サーバーが送信中の件があるなどの理由で断る
- **THEN** 表は残り、理由が表の上の知らせの場所に、エラーの知らせとして出る
