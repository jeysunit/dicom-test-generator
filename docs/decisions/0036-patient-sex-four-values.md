# ADR-0036: 性別は製品の中で M・F・O・U の 4 値にし、DICOM に書くときは U を空にする

- 状態：採用
- 作成日：2026-10-31
- 最終更新日：2026-10-31

## 背景

DTG の性別は M・F・O の 3 値で、DICOM の Patient's Sex（0010,0040）の列挙値と同じだった。
ワークリストの応答で性別が空のとき、画面は「不明」と出したが、製品の中の値は空のままで、
「わからない」を選ぶ手段が画面に無かった。

3 製品（tsunagi-dicom・ris-emulator・DTG）と部品集 ui-kit 1.2.5 は、性別を M・F・O・U の
4 値にそろえた。わからない・言えないは U。ただし DICOM の列挙値は M・F・O だけで、U は規格の外にある。

## 決定

1. **製品の中の値と画面の値は M・F・O・U の 4 値にする。** 画面の表示は「男・女・その他・不明」で、
   値の文字は画面に出さない。撮影の画面の性別の選択肢に「不明」を足す
2. **DICOM に書くときは U を空にする。** 撮影した画像と MPPS の Patient's Sex が対象で、
   Type 2 の空で書く。規格の列挙値の外の値を作らない
3. **DICOM から読むときは、空と M・F・O 以外を U と読む。** ワークリストの応答の性別が対象。
   これまで規格外の値は「予約の性別が M・F・O・空のどれでもありません」で撮影を断っていたが、
   U と読んで通す。撮影の画面と CLI は「性別が不明です」と知らせる
4. **変換は `app/core/patient_sex.py` の 2 つの関数に置く。** 書く側（`to_dicom_sex`）と
   読む側（`from_dicom_sex`）を 1 か所にし、書く場所が増えても U が漏れないようにする

## 検討した選択肢

- **U を DICOM にそのまま書く。** 列挙値の外で、受け側が拒否するか、黙って捨てる。採用しない
- **3 値のまま、わからないを空で表す。** 画面で「不明」を選べず、空（まだ選んでいない）と
  区別できない。採用しない
- **規格外の値をこれまでどおり断る。** 相手の RIS の値で撮影が止まる。ワークリストは
  相手から来る値で、DTG が直せないため採用しない

## 結果

- 画面・ジョブの YAML・CLI の `--sex`・患者マスターが 4 値を受ける
- 画像と MPPS の PatientSex は M・F・O・空のいずれかになる
- 保存済みの緊急の患者の記録（SQLite）の性別が空でも、そのまま読め、書くときは空になる
