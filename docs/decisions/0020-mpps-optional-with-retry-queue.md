# ADR-0020: MPPS を送信できなくても撮影を止めず、未送信の通知はキューに残して再送する

- 状態：採用
- 日付：2026-10-19
- 作成日：2026-10-22

## 背景

MPPS（N-CREATE・N-SET）は、撮影の開始と終了を相手に通知する。主なテスト相手の
Orthanc は MPPS を受け付けない（DICOM Conformance Summary に記載が無く、
`CommandDispatcher.cpp` も処理しない）。MPPS を受け付ける相手でも、テストの途中で
停止していることがある。送信先、送信のタイミング、送信できなかったときの扱い、
「取り消し」の意味を決める必要があった。

## 決定

1. **MPPS は `worklist.use_mpps: true` のときだけ送信し、送信先は `modality.mpps:`
   の相手（設定が無ければワークリストの取得先）にする。** CLI の `exam --mpps`・
   `--no-mpps` は、その撮影だけ設定を上書きする。装置プロファイルが
   `services.mpps: false` なら送信しない
2. MPPS を送信できなくても、撮影と画像の送信は止めない。未送信の通知は状態の保存先
   の MPPS のキューに残し、`retry.max_attempts` の回数だけすぐに再送する。残った分は
   CLI の `mpps retry` で送信する。理由：撮影のたびに残りを自動で再送すると、相手が
   停止しているとき、撮影のたびにタイムアウトを待つことになる
3. 「取り消し」は、N-CREATE の後に撮影が止まったときに DISCONTINUED を送信すること
   とする。画面と CLI に、撮影を取り消す操作は持たない
4. 送信できたとみなすのは、相手が Success か Warning を返したときだけにする。例外は
   2つで、どちらも、前に同じ通知を送信して応答が無かったことを記録から確認できる
   ときに限る
   - N-CREATE に `0x0111`（同じ SOP Instance が既に存在する）が返った
   - 終了の N-SET に `0x0110`（完了した MPPS は更新できない。PS3.4 F.7.2.2）が返った

   理由：`0x0110` は処理失敗の一般的な値でもあるので、前に送信していない場合や、
   前に相手が Failure を返していた場合は、届いていたとは言えない
5. 再送の送信先は、N-CREATE を作成したときの相手に固定する。設定を後で変えても、
   新しい相手には送信しない。元の相手に IN PROGRESS が残ることと、別の相手に患者の
   値を送信することを避けるため
6. 画面には状態を表示するだけにし、再送のボタンは追加しない

## 検討した選択肢

- **MPPS を必須にする**：Orthanc を相手にすると処理が止まる
- **撮影のたびに残りを自動で再送する**：相手が停止しているとき、撮影のたびに
  タイムアウトを待つ
- **取り消しのボタンを画面に戻す**：画面の機能は追加するより減らすという方針に
  合わない
- **`0x0110` を常に送信成功として扱う**：処理失敗の一般的な値と区別できない

## 結果

- MPPS を受け付けない相手でも、撮影と送信の流れをテストできる
- 未送信の通知は `mpps list` で確認でき、`mpps retry` で送信できる
- 同じ行を2つの処理が同時に送信しないよう、行に送信権を持たせる必要がある
  （spec/12 の 8.4.1）
