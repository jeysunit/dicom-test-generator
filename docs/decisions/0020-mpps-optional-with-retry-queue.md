# ADR-0020: MPPS は送れなくても撮影を止めず、送れない通知はキューに残して送り直す

- 状態：採用
- 日付：2026-10-19
- 作成日：2026-10-22

## 背景

MPPS（N-CREATE・N-SET）は、撮影の開始と終了を相手に通知する。主な試験の相手の
Orthanc は MPPS を受けない（DICOM Conformance Summary に無く、
`CommandDispatcher.cpp` も扱わない）。MPPS を受ける相手でも、試験の途中で
止まっていることがある。送り先・送るとき・送れなかったときの扱い・
「取り消し」の意味を決める必要があった。

## 決定

1. **MPPS は `worklist.use_mpps: true` のときだけ送り、送り先は `modality.mpps:`
   の相手（書いていなければワークリストの相手）にする。** CLI の
   `exam --mpps`・`--no-mpps` は、その撮影だけ設定を上書きする。装置の
   プロファイルが `services.mpps: false` なら送らない
2. **MPPS が送れなくても、撮影と画像の送信は止めない。** 送れない通知は
   状態の置き場の MPPS のキューに残し、`retry.max_attempts` の回数だけすぐに
   送り直す。残った分は CLI の `mpps retry` で送る。理由：撮影のたびに残りを
   自動で送り直すと、相手が止まっているとき、撮影のたびに時間切れを待つことになる
3. **「取り消し」は、N-CREATE の後に撮影が止まったときに DISCONTINUED を送る
   ことにする。** 画面と CLI に撮影を取り消す操作は持たない
4. **送れたとみなすのは、相手が Success か Warning を返したときだけにする。**
   例外は2つで、どちらも、前に同じ通知を送って応答が来なかったと記録から
   言えるときに限る
   - N-CREATE に `0x0111`（同じ SOP Instance が既にある）が返った
   - 終わりの N-SET に `0x0110`（終わった MPPS は更新できない。PS3.4 F.7.2.2）が
     返った

   理由：`0x0110` は処理の失敗の一般の値でもあるので、前に送っていない、
   前に相手が Failure を返していた、というときは届いたとは言えない
5. **送り直しの送り先は、N-CREATE を作ったときの相手に固定する。** 設定を後で
   変えても、新しい相手には送らない。元の相手に IN PROGRESS が残ることと、
   別の相手に患者の値を送ることを避けるため
6. **画面には状態を出すだけにし、再送のボタンは足さない**

## 検討した選択肢

- **MPPS を必須にする**：Orthanc を相手にすると流れが止まる
- **撮影のたびに残りを自動で送り直す**：相手が止まっているとき、撮影のたびに
  時間切れを待つ
- **取り消しのボタンを画面に戻す**：画面の機能を足すより削る方針に合わない
- **`0x0110` をいつも送れた扱いにする**：失敗の一般の値と区別できない

## 結果

- MPPS を受けない相手でも、撮影と送信の流れを試せる
- 送れていない通知は `mpps list` で見え、`mpps retry` で送れる
- 同じ行を2つの手順が同時に送らないよう、行に「送る権利」を持たせる必要がある
  （spec/12 の 8.4.1）
