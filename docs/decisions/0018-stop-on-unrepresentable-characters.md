# ADR-0018: 画像の文字コードで表現できない文字があれば、その画像を書き出さずに停止する

- 状態：採用
- 作成日：2026-10-22
- 最終更新日：2026-10-22

## 背景

画像の Specific Character Set は、デフォルトの文字セット（ASCII）に無い文字を使う
ときに必須になる（PS3.3 C.12.1 の Type 1C、PS3.5 6.1）。宣言した文字コードで
表現できない文字を書き出すと、pydicom は `?` に置き換えるか、宣言に無いバイト列の
まま書き出す。どちらの場合も、利用者が気付かないうちに、規格に合わない画像や値の
変わった画像ができる。

表現できない文字は、ワークリストの予約（UTF-8 の予約にある、JIS X 0208 に無い文字
など）からも、Job の値（文字コードが空の病院テンプレートでの漢字や `é` など）からも
来る。

## 決定

1. **画像を1枚書き出す前に、その画像のすべての文字列の属性を検証し、表現できない
   文字があれば、その画像を書き出さずに停止する。** 黙って削除したり `?` に置き
   換えたりしない
2. エラーの種類は経路で分ける。予約からの撮影は `WorklistMappingError`、Job の
   生成は `DICOMValidationError`。どちらも CLI の終了コードは 4
3. 検証は、エンコードしてからデコードし、元の文字に戻るかで行う
   （`pydicom.charset`）。ISO 2022 IR 13 では `¥`・`‾` が 0x5C・0x7E になり、
   デコードすると `\`（値の区切り）・`~` に変わるので、表現できない文字として扱う
4. エラーメッセージとログには、属性の名前と文字コードだけを出す。表現できない文字
   そのもの（氏名の一部など）は出さない

## 検討した選択肢

- **表現できない文字を `?` に置き換えて撮影する**：値が変わったことに利用者が
  気付けない。異常のデータの一つとして明示的に選んだときだけ行う案もあるが、
  その選択肢はまだ実装していない
- **pydicom に任せる**：バージョンによって、置き換えるか生のバイト列で書き出すかが変わり、
  結果を予測できない

## 結果

- 生成した画像は、宣言した文字コードで必ずデコードできる
- 1回の生成の途中で停止したとき、それより前に書き出した画像は残る。予約からの
  撮影で、撮影のために作成した出力フォルダが空のまま残るときは、そのフォルダも
  削除する
