# ADR-0018: 画像の文字コードで表せない字があれば、その画像を書かずに止める

- 状態：採用
- 日付：2026-10-21
- 作成日：2026-10-22

## 背景

画像の Specific Character Set は、既定の字の集まり（ASCII）に無い字を使うときに
必須になる（PS3.3 C.12.1 の Type 1C、PS3.5 6.1）。宣言した文字コードで
表せない字を書くと、pydicom は `?` に置き換えるか、宣言に無いバイトのまま書く。
どちらも、利用者が気づかないうちに規格に合わない画像や、値の変わった画像が
できる。

表せない字は、ワークリストの予約（UTF-8 の予約にある JIS X 0208 に無い字など）
からも、Job の値（文字コードが空の病院テンプレートでの漢字や `é` など）からも
来る。

## 決定

1. **画像を1枚書く前に、その画像のすべての文字の属性を確かめ、表せない字が
   あれば、その画像を書かずに止める。** 黙って消したり `?` に置き換えたりしない
2. **誤りの種類は経路で分ける。** 予約の撮影は `WorklistMappingError`、
   Job の生成は `DICOMValidationError`。どちらも CLI の終了コードは 4
3. **確かめは、書いて読み戻して元の字に戻るかで行う**（`pydicom.charset`）。
   ISO 2022 IR 13 では `¥`・`‾` が 0x5C・0x7E になり、読み戻すと `\`
   （値の区切り）・`~` に化けるので、表せない字として扱う
4. **誤りの文とログには、属性の名前と文字コードだけを出す。** 表せない字
   そのもの（氏名の一部など）は出さない

## 検討した選択肢

- **表せない字を `?` に置き換えて撮る**：値が変わったことに利用者が
  気づけない。異常のデータの一つとして明示して選んだときだけ行う案もあるが、
  その選択はまだ作っていない
- **pydicom に任せる**：版によって置き換えるか生のバイトで書くかが変わり、
  結果を予測できない

## 結果

- 作った画像は、宣言した文字コードで必ず読み戻せる
- 1回の生成の途中で止まったとき、それより前に書いた画像は残る。予約の撮影で、
  撮影のために作った出力のフォルダが空のまま残るときは、そのフォルダも消す

## 出典

- DICOM PS3.3 C.12.1・C.12.1.1.2、PS3.5 6.1
