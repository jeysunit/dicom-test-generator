# ADR-0029: 身元不明の患者は、仮の ID と空の英字の氏名で撮れるようにする

- 状態：採用
- 作成日：2026-10-26
- 最終更新日：2026-10-28

## 背景

救急では、身元不明の患者を、仮の患者ID と仮の氏名で撮り、後で RIS が正式な患者に
照合する（IHE PIR の Case 6）。これまでの撮影の画面は、英字の氏名を必須にして欄の先頭に
置いていた。身元の分からない患者では英字の氏名が書けず、患者ID も決めようがなかった。
UX のレビュー（D5）がこの点を挙げた。

分かっている事実：

- PN は、前の群が空でも後ろの群を書ける（PS3.5 6.2.1）。`=山田^太郎=ヤマダ^タロウ` の
  ように、先頭の `=` で英字の群が空だと表す。pydicom と ISO 2022 IR 87 の符号化で、
  `utf8`・`jis`・`jis_kana` の3つを往復して確かめた
- ris-emulator は MPPS の PatientName を群の番号で読み、空の英字の群を許す。患者ID は
  DTG と同じ規則（64 字・HL7 v2 の区切りなし）で確かめる

## 決定

1. 撮影の画面の欄の順は、患者ID・氏名（漢字）・氏名（かな）・氏名（英字）・生年月日・
   性別とする。必須は患者ID・氏名（漢字）・性別とし、英字の氏名は任意にする。現場で
   分かる順に入れられるようにするため
2. 漢字と性別の必須は、画面（`POST /exam`）だけに課す。サービスと CLI は、患者ID と、
   氏名の3つの群のどれか1つがあればよいとする。追加撮影は、画面でもこの必須を課さない
   （患者の値は、前の撮影と一致するかで確かめる）。CLI と API の既存の呼び出しを壊さず、
   画面の入力だけを現場の運用にそろえるため
3. 仮の患者ID は、設定の頭（既定 `TMP`）と、設定のタイムゾーンの日時（`YYYYMMDDHHMMSS`）で
   作る。作るのはサーバーで、渡した ID を覚え、同じ秒の2つ目からは `-2`・`-3` を付けて重ならない
   ようにする（時計が戻って同じ秒を通り直しても、覚えた ID とは重ならない。覚えた集合は
   プロセスの中だけで、1回に1件ずつ増える）。
   時計をサーバーに置くのは、ブラウザの時計とタイムゾーンに頼らず、検査日と同じ時計に
   そろえるため
4. 氏名が分からないときは、設定の漢字（既定「不明^不明」）とかな（既定「フメイ^フメイ」）を
   使い、英字は空にする。画面は選択で値を欄に入れて読むだけにし、サーバーも選択を受けたら
   入力の値によらず置き換える（スクリプトが無くても同じ値になる）
5. 頭と氏名不明の値は設定（`modality.temporary_patient_id_prefix`・
   `unknown_name_ideographic`・`unknown_name_phonetic`）で変えられる。設定の読み込みで、
   患者ID と氏名の規則に合うかを確かめる。氏名（漢字）は、設定の文字コードで表せるかも
   確かめる

## 検討した選択肢

- **氏名不明を「氏名が空」で表す**：RIS が仮の患者と未入力を区別できず、一覧にも出ない。
  採用しなかった
- **仮の ID をブラウザの時計で作る**：ブラウザのタイムゾーンに頼り、同じ秒の2回押しを
  サーバーが防げない。採用しなかった
- **漢字と性別の必須をサービスにも課す**：CLI・API の既存の使い方と試験が壊れる。
  採用しなかった

## 結果

- 身元不明の患者を、患者IDの決定と氏名の入力に迷わず撮れる。撮った後の RIS の照合に使える
- 画像・MPPS の PatientName の先頭が `=` になる。先頭の群を常に氏名とみなす受け側では、
  氏名が空に見える。PACS・RIS の側でこの形を扱えるかを試験できる
- 重ならない保証は、この画面のプロセスの中だけ。別のプロセス（CLI など）が同じ秒に
  同じ頭で作ることは防がない
