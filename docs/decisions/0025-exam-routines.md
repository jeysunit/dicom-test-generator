# ADR-0025: 撮影は既定で予約に当てたルーチンの並びと枚数で行う

- 状態：採用
- 作成日：2026-10-24
- 最終更新日：2026-10-24

## 背景

撮影の画面と CLI の `exam` は、シリーズ数と画像数を利用者が毎回入れていた。作る
画像はどのシリーズも CT の軸位の画像（Image Type `ORIGINAL\PRIMARY\AXIAL`）で、
Series Description を持たなかった。実際の CT の検査では、位置決めの画像、軸位の
再構成、冠状断・矢状断の画像、線量の画面が、部位ごとに決まった並びで PACS に
届く。PACS のシリーズの並べ方・位置決めの扱い・線量の集計を試すには、この並びに
近い検査が要る。テストデータを作るツールなので、枚数を利用者に考えさせない。

公開の資料から、次のことが分かった（調べた内容と出典は
`openspec/changes/archive/2026-10-24-add-exam-routine-templates/design.md`）。

- CT の1シリーズ目は位置決めの画像で 1〜2 枚、最後は線量の画面（Secondary
  Capture）が多い。中間のシリーズは部位・目的ごとに決まる
- MR のローカライザーは 3面を1シリーズに入れ、1面に 5〜8 枚
- CR は View Position (0018,5101) が CR Series Module にある（PS3.3 C.8.1.1）。DX は
  画像ごとの DX Positioning Module にある（PS3.3 C.8.11.5）
- 中間の断面のシリーズの枚数を載せた公開の資料はほとんど無い

## 決定

1. 撮影のルーチン（部位ごとのシリーズの並びと画像数）を `templates/routine/` の
   YAML に置く。どのシリーズも既定の画像数を持つ。中間のシリーズの画像数は、
   資料のスライス厚と想定した撮影範囲から計算する
2. ルーチンの形はモダリティごとに変える。CT はシリーズの種類（位置決め・軸位・
   冠状断・矢状断・線量の画面）と再構成、MR はシーケンス、CR は方向ごとに1シリーズ
   1枚、DX は1シリーズに全部の方向、US は静止画と動画の数。DTG が扱うモダリティ
   （CT・MR・CR・DX・US）のルーチンを付ける
3. 撮影の画面と CLI は、既定で予約に当てたルーチンで撮る。予約の Requested
   Procedure Description、Scheduled Procedure Step Description、Body Part
   Examined の順に見て、ルーチンの `keywords`（見出しの言葉）が含まれるルーチンを
   当てる。先の欄で当たれば後の欄は見ない。1つの欄では長い語、同じ長さなら前に
   出てくる語を選ぶ。欄と語は NFKC で正規化し、大文字と小文字を区別しない。当たら
   なければモダリティの既定のルーチン。施設の検査のコードの対応表は持たない
4. 今の手入力（シリーズ数・画像数）は選択肢の最後の「手で入れる」として残す。CLI は
   `-s`・`-i` で手入力、`--routine` でルーチンを選ぶ。サービスの `ExamRequest` は
   `routine` を省くと今までどおり手入力で撮る（スクリプトの互換のため）
5. CT のシリーズの種類に合わせて、Image Type・Image Orientation (Patient)・SOP
   Class を変える。位置決めは `ORIGINAL\PRIMARY\LOCALIZER`、冠状断と矢状断は
   `DERIVED\SECONDARY\AXIAL`（PS3.3 C.8.2.1.1.1 の注のとおり断面の画像は AXIAL）。
   線量の画面は Secondary Capture Image Storage（Modality は CT、Conversion Type
   `WSD`、8 ビットの MONOCHROME2）で、架空の CTDIvol・DLP を描く。RDSR は作らない
6. シリーズ番号はルーチンに書ける（999・501 など）。予約ごとに使った番号と、書いた
   番号か自動かを記録する。自動の番号は自動で付けた番号の最大の次にし、使った
   番号を飛ばす。書いた番号が使った番号と同じなら撮影せずに止める
7. MR・CR・DX・US の画像を作る処理は、この ADR の範囲に入れない。それまでは、
   今の決まりどおり、予約とテンプレートのモダリティが違えば撮影しない

## 検討した選択肢

- シリーズの種類を作らず、CT の軸位の画像のまま Series Description と枚数だけを
  変える：作りは小さいが、PACS の位置決めの扱いや線量の画面の読み取りを試せない
- 利用者が画面でルーチンを選ぶだけにする：当て方の作りは要らないが、撮影のたびに
  選ぶ手間がかかり、テストデータを作るツールの目的に合わない
- 予約の検査のコード（Scheduled Protocol Code Sequence など）で当てる：施設ごとの
  コードの対応表が要る。見出しの言葉なら付けるルーチンだけで当たる
- 自動の番号を固定の境（900 未満）までにする：501 のように境より小さい書いた番号と
  ぶつかる

## 結果

- 予約を選んで「撮影」を押すだけで、部位に合ったシリーズの並びと枚数の検査が
  できる。胸部 単純は 6 シリーズ・505 枚
- 既定の撮影の枚数が増える。`-s`・`-i` を省いて1シリーズ1枚を前提にしていた試験と
  スクリプトは、`-s 1` を付ける
- シリーズ番号の記録の表（`exam_series_numbers`）が増える。前の版の記録は、
  1〜シリーズの数を自動で使ったとみなす
- 線量の画面の値は架空で、実の線量の確かめには使えない

## 決めないこと

- MR・CR・DX・US の画像の作り方（Image Type・SOP Class・動画）
- US の甲状腺・乳腺・心エコーのルーチン（資料の本文で枚数を確かめられなかった）
