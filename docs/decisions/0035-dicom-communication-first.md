# ADR-0035: DTG の主な機能を DICOM 通信にし、ファイルへの出力は単独で使うために残す

- 状態：採用
- 作成日：2026-10-31
- 最終更新日：2026-11-01

## 背景

DTG は、最初はデスクトップの GUI で動く、DICOM ファイルの生成ツールだった。主な機能は
ファイルの出力で、DICOM 通信は付け足しだった。その後、tsunagi の開発を始めると、使われ方が
変わった。今の DTG は、モダリティとして RIS からワークリストを取得し、撮影し、PACS へ
送信し、保管確認と MPPS を扱う。テストの価値は、この通信の流れにある。

文書には、ファイルの出力を主な機能、モダリティの動作を補助の機能とする古い位置づけが
残っていた（README・project_charter・architecture・openspec/config.yaml）。
[ADR-0011](0011-modality-emulator.md) は通信を足した判断で、位置づけの逆転までは
決めていない。

## 決定

1. **主な機能は、モダリティとして振る舞う DICOM 通信とする。** ワークリストの取得、撮影、
   C-STORE での送信、保管確認、MPPS を指す。README・charter・architecture は、この通信を
   先に書く
2. **ファイルへの出力は、残す機能とする。** DICOM 通信だけのツールでは単独のアプリとして
   役に立たないため。CLI の `generate`・`quick` と、撮影で出力フォルダに書くファイルを
   含め、機能は削らない
3. **コードと動作は変えない。** この ADR は文書の位置づけだけを直す。spec の動作の記述は
   変わらない

## 検討した選択肢

- **ファイルの出力を主な機能のままにする。** 今の使われ方と合わない。採用しない
- **ファイルの出力を削り、通信だけにする。** 通信の相手が無い環境で画像を作れなくなり、
  単独で使えない。採用しない

## 結果

- 文書の説明が、実際の使われ方と合う
- ADR-0011 は「ファイルの生成までだった」という当時の背景を書いたまま残る。この ADR が
  位置づけについては、この ADR が現在の決めである
