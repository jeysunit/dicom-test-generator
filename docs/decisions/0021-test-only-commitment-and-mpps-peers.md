# ADR-0021: 保管確認と MPPS の SCP は、試験の中にだけ立てる

- 状態：採用
- 日付：2026-10-19
- 作成日：2026-10-22

## 背景

保管確認と MPPS を試すには、N-ACTION に答えて N-EVENT-REPORT を返す相手と、
N-CREATE・N-SET を受ける相手が要る。これらをこのツールの機能として持つか、
試験の中にだけ置くかを決める必要があった。

## 決定

1. **保管確認の SCP と MPPS の SCP は、試験の中のスタブ
   （`tests/modality_peers.py`）だけで作る。このツールの機能として、受ける側を
   持たない。** 理由：ワークリストの SCP（RIS の役）を試験の中だけで立てるのと
   同じ決まりにそろえる。受ける側を持つと、受けた画像の台帳、結果を返す先の設定
   （相手の AE タイトル・ホスト・ポート）、MPPS の保存が要り、試験の相手として
   機能が増える
2. **スタブは、結果を返す経路（同じ Association・別の Association）、返す
   Status、返す値を試験ごとに変えられるようにする**
3. **手で試すときは、外の相手を使う。** 保管確認は Orthanc を相手にする。
   MPPS は、MPPS を受ける RIS などが要る（Orthanc は受けない）

## 検討した選択肢

- **ローカルで受ける側に、保管確認の SCP と MPPS の SCP の最小の形を足す**：
  受けた画像の台帳と、結果を返す先の設定が要る。機能を足すより削る方針に
  合わない

## 結果

- このツールが持つ待ち受けは、保管確認の結果を受ける小さなもの
  （`modality.listen`）だけになる
- このツールだけでは、保管確認と MPPS の流れを手で試せない。外の相手を用意する
