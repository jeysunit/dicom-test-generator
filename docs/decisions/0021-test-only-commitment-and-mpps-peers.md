# ADR-0021: 保管確認と MPPS の SCP は、テストの中だけで起動する

- 状態：採用
- 日付：2026-10-19
- 作成日：2026-10-22

## 背景

保管確認と MPPS をテストするには、N-ACTION に応答して N-EVENT-REPORT を返す相手と、
N-CREATE・N-SET を受け付ける相手が必要になる。これらを DTG の機能として持つか、
テストの中だけに置くかを決める必要があった。

## 決定

1. **保管確認の SCP と MPPS の SCP は、テストの中のスタブ
   （`tests/modality_peers.py`）としてだけ実装する。DTG の機能として受信側を
   持たない。** 理由：ワークリストの SCP（RIS の役）をテストの中だけで起動するのと
   同じ規則にそろえる。受信側を持つと、受信した画像の台帳、結果の返送先の設定
   （相手の AE タイトル・ホスト・ポート）、MPPS の保存が必要になり、テスト相手と
   しての機能が増える
2. スタブは、結果を返す経路（同じ Association・別の Association）、返す Status、
   返す値をテストごとに変えられるようにする
3. 手動でテストするときは、外部の相手を使う。保管確認は Orthanc を相手にする。
   MPPS は、MPPS を受け付ける RIS などが必要（Orthanc は受け付けない）

## 検討した選択肢

- **ローカルの受信側に、保管確認の SCP と MPPS の SCP の最小限の実装を追加する**：
  受信した画像の台帳と、結果の返送先の設定が必要になる。機能は追加するより減らす
  という方針に合わない

## 結果

- DTG が持つ待ち受けは、保管確認の結果を受ける小さなもの（`modality.listen`）
  だけになる
- DTG だけでは、保管確認と MPPS の流れを手動でテストできない。外部の相手を用意する
