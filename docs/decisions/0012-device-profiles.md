# ADR-0012: 装置プロファイルで装置の出力を再現する（仕組みは公開・実在の装置のプロファイルは非公開）

- 状態：採用
- 日付：2026-10-20
- 作成日：2026-10-18

## 背景

元のモダリティテンプレートは、実在の装置のコンフォーマンス
ステートメント（DICOM PS3.2）を読み、その装置の DICOM の出力を
再現するためのものだった。テンプレートの名前と内容に実在の製品の名前が
入っていた。

[ADR-0016](0016-generic-template-names.md)（公開のテンプレートに商用製品の名前を使わない）を
採用した PR（#5）で、そのテンプレートを架空の名前の `ct_generic` に変え、
spec/06 からコンフォーマンスステートメントの行を削除した。このとき
テンプレートの目的（装置の再現）を確認しておらず、再現の仕組みそのものが
無くなった（誤り）。

### 要求

- 特定の装置が出力する形の DICOM を、本物の装置なしで生成できる
- 公開のリポジトリに、実在の製品の名前・実在の装置から転記した内容を置かない
- 転記元（どの文書のどの版か）を記録できる
- 転記の手順が文書になっている（担当者が替わっても転記できる）

## 決定

1. **案 A：再現の仕組みは公開し、実在の装置から転記したもの（プロファイル）は
   公開しない。** 仕様は
   [spec/13_device_profiles.md](../spec/13_device_profiles.md)
2. **プロファイルはモダリティテンプレートの上に重ねる（置き換えない）。**
   順は Job → テンプレート → プロファイル → 病院テンプレート。装置の値
   （製造者・型名・ソフトウェアの版・装置の番号・Implementation Version
   Name・SOP Class）は病院テンプレートでも変えない
3. **実在の装置のプロファイルは外部のフォルダ（`DTG_PROFILE_DIRS`・
   `profiles.search_paths`）から読み込む。** リポジトリの `profiles/` には
   架空の例（`profiles/examples/`）だけを置き、`.gitignore` とテストで
   ほかのものが入らないようにする
4. **同じ名前のプロファイルが2か所以上にあればエラーにする。** 上位の配置場所が
   黙って下位を隠さない
5. **未知のフィールド・合わない値（モダリティ・Transfer Syntax・文字コード）は
   エラーにする。** 黙って修正しない・無視しない
6. **古い名前のテンプレートを指定されたら、プロファイルの配置場所を
   案内するエラーにする**（古い名前は今と同じく SHA-256 で持つ）

### 理由

#### 1. 案 A を選ぶ理由

| 案 | 内容 | 良い点 | 悪い点 |
|----|------|--------|--------|
| **A. 仕組みは公開・転記したものは非公開（採用）** | 仕組み・例は公開、実在の装置から転記したものは外部の配置場所 | 仕組みを公開でテスト・レビューできる。製品の名前が公開されない | 転記したものの配置場所を利用者が持つ |
| B. 転記したものも公開 | 元のテンプレートの形に戻す | 手間が少ない | 実在の製品の出力と誤解されうる。ADR-0016 と合わない |
| C. 仕組みごと非公開 | 再現の機能を外部のツールにする | 公開の側は単純 | 仕組みのテスト・レビューが公開でできない。二重の保守 |

#### 2. 重ねる理由（置き換えない理由）

- コンフォーマンスステートメントに書いてあるのは属性の出力方法で、撮影の
  値（kVp・スライス厚・ウィンドウ）は書いていない。撮影の値はテンプレートが持つ
- 1つのテンプレートに複数の装置を重ねられる
- 置き換えにすると、テンプレートのフィールドの転記漏れが黙って既定値になる

#### 3. 同じ名前をエラーにする理由

- 先に見つかったほうを使うと、例のプロファイルと非公開のプロファイルの
  どちらで生成したかが、出力を見ても分からない
- 名前を変えれば済むので、エラーにしても困らない

#### 4. 装置の値を病院テンプレートで変えない理由

- 施設の設定で変わるのは施設の名前・Station Name・文字コードで、装置の
  製造者・型名・ソフトウェアの版は変わらない
- 今の病院テンプレートのマージは浅い（`general_equipment` を丸ごと
  置き換える）ので、プロファイルの値を病院の前に置くと黙って消える

## 影響

### 良い点

- 装置を再現する仕組みが戻る
- 転記元（`source`）がプロファイルに残る
- 公開の側に実在の製品の名前を書かずに済む

### 悪い点

- 実在の装置のプロファイルは、利用者が非公開の場所で持ち、転記した内容を保守する
- P1 で反映されるのは装置の値・Transfer Syntax・文字コード・属性・プライベートタグ
  まで。UID の形式・画素・シリーズの並び（P2）、ワークリスト（3a）、
  MPPS・保管確認（3c）は後のフェーズ
  - 追記（2026-10-20）：MPPS・保管確認（`services.mpps`・
    `services.storage_commitment`）は実装済み。UID の形式・画素・シリーズの
    並び（P2）とワークリストのフィールドは未実装（spec/13 の 11 章）

### リスク

- 非公開のプロファイルを誤って公開の側に置く
  - **軽減策**：`.gitignore` で `profiles/` の下を例以外すべて除外する。
    テストで、リポジトリに例しか無いことを確認する
- 転記した値の誤り（文書の読み違い）
  - **軽減策**：転記の手順（spec/13 の 5 章）と、生成した画像を文書の表と
    並べて確認する手順を文書にする
