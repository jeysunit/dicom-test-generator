# 12a. モダリティエミュレーター：Web 画面と CLI

この文書は、モダリティエミュレーターのうち利用者が操作する部分（Web 画面と CLI）を
定める。通信・予約の値の転記・送信・モジュールと配置・設定・ログは
[12_modality_emulator.md](12_modality_emulator.md) にある。

章番号は spec/12 から続けて振っている。この文書は 10 章（Web 画面）と 11 章
（CLI）を持つ。本文の「5.5」「8.3.3」のような番号だけの参照は spec/12 の章を
指す。

設計の判断：[ADR-0011](../decisions/0011-modality-emulator.md)

---

## 10. Web 画面

### 画面の方針

**画面はすっきりさせる。余白を取り、部品を少なくし、一画面で行う操作を1つに
する。** クラウド型の電子カルテのような、余白の多い落ち着いた画面を目安にする。
例外は無い。

- DTG は診療のためではなく、システムのテストでモダリティの代わりに使う。技師の
  操作をすべて再現する必要は無く、テストに必要な「取得→選択→撮影→送信→確認」を
  迷わず実行できればよい
- **機能は追加するより減らす。** 画面に何かを追加したくなったら、まずテストに必要
  かを検討する。不要なら追加しない。CLI か設定ファイルでできることは、画面に
  出さなくてよい
- 一画面のプライマリボタンは1つにする（例：ワークリストは「選んで撮影へ」、撮影は
  「撮影して送る」）。ほかの操作は枠線のボタンか背景の無いボタンにして目立たない
  ようにする
- 詳しい値（予約の値の全部・UID など）は最初から並べず、開いて表示する
  （パネル・折りたたみ）

### 10.1 技術

**画面は、サーバー側で描画する Web 画面（FastAPI・Jinja2・HTMX・Tailwind CSS の
standalone の実行ファイル）にする。** 選んだ理由は ADR-0011 にある。

- Node は不要。Tailwind CSS v4 は standalone の実行ファイル（GitHub の
  releases に OS ごとの実行ファイルと `sha256sums.txt` がある）で CSS を作成できる。
  バージョンを固定し、sha256 を検証してから使う
- 作成した CSS（`app/web/static/app.css`）は commit する。利用者は Tailwind の
  実行ファイル無しで動かせる
- htmx は1つの JavaScript のファイルを `app/web/static/` に置く（バージョンを固定
  し、入手元と sha256 を [development.md](../development.md) の 5 章に書く）。外部の
  CDN からは読み込まない。ネットワークに接続しない環境でも動かすため
- アイコンは Lucide（ISC License）の SVG を、使う分だけ `app/web/static/icons/`
  に置く。ライセンスの文を同じ場所に置く
- Python のパッケージは `fastapi`・`uvicorn`・`jinja2`・`python-multipart`
  （フォーム）、テスト用に `httpx`（FastAPI の TestClient が使う）
- 画面の更新（送信キューの状態など）は HTMX の定期的な取得
  （`hx-trigger="every 2s"`）で行う。SSE・WebSocket は使わない
- 色と文字の値は、入力の CSS（`app/web/styles/input.css`）に書く。値が 10.2 の表と
  ずれたら検出できるよう、テストで比較する（`tests/web/test_theme_tokens.py`）

### 10.2 見た目の基準

**画面（ワークリスト・撮影・PACS・設定）は、ライトテーマを既定にし、
ダークテーマにも切り替えられる。** 例外は1つ：画像のサムネイルを並べる部分だけ、
周囲をダークテーマにする。

- これらは文字を読む画面である。日本の医療機関で広く使われている画面でも、画像を
  見る画面は暗い背景、一覧や事務の画面は明るい背景が多い
- テーマの切り替えはヘッダーのボタンで行い、ブラウザの `localStorage` に
  保存する。保存されていなければライトテーマ
- どちらのテーマでも、基準の文字は 14px（0.875rem）・行間 1.5。表の行・入力欄も
  14px を下回らない（補足の文字だけ 12px）
- 部品の間の余白は広めに取り、詰めない：パネルの間は 16〜24px、パネルの中の
  入力欄の間は 12px 以上、ページの左右は 16px 以上。1画面に詰め込まず、詳細は
  パネルを開いて表示する
- 文字と背景のコントラスト比は WCAG 2.2 の AA（4.5:1）以上にする

| 名前 | ライトテーマ（既定） | ダークテーマ | 用途 |
|------|----------------------|--------------|------|
| `--color-background` | `#ffffff` | `#121417` | 背景 |
| `--color-surface` | `#f6f8fa` | `#1a1d21` | ヘッダー・パネルの背景 |
| `--color-foreground` | `#1f2328` | `#e6edf3` | 文字 |
| `--color-label` | `#59636e` | `#8a949e` | ラベル |
| `--color-value` | `#1f2328`（太字） | `#ffffff`（太字） | 値 |
| `--color-border` | `#d1d9e0` | `#2a2f36` | 枠線 |
| `--color-muted` | `#eff2f5` | `#23272d` | 行の hover・弱い背景 |
| `--color-primary` | `#0969da` | `#1f6feb` | プライマリボタン・フォーカスリング |
| `--color-primary-foreground` | `#ffffff` | `#ffffff` | プライマリボタンの文字 |
| `--color-danger` | `#d1242f` | `#ff7b72` | 失敗・停止の通知の文字 |
| `--color-success` | `#1a7f37` | `#3fb950` | 撮影完了・送信完了の枠と印 |
| `--color-warning` | `#9a6700` | `#d29922` | 注意（予約なし・生年月日が空など）の枠と印 |
| `--font-sans` | `system-ui, "Noto Sans JP", sans-serif` | 同じ | 本文 |
| `--font-mono` | `ui-monospace, "Noto Sans Mono", monospace` | 同じ | UID |

- コントラスト比（WCAG 2.x の相対輝度の式で計算）：ライトテーマの文字 `#1f2328`
  は `#ffffff` に 15.8:1・`#f6f8fa` に 14.8:1、ラベル `#59636e` は 6.1:1・5.7:1。
  ダークテーマの文字 `#e6edf3` は `#121417` に 15.6:1、ラベル `#8a949e` は
  `#1a1d21` に 5.5:1。いずれも AA を満たす
- ライトテーマの `--color-muted`（`#eff2f5`）の上で、文字 `#1f2328` は 14.1:1、
  ラベル `#59636e` は 5.4:1、プライマリカラー `#0969da` は 4.6:1 で、どれも AA を満たす。
  ダークテーマの `#23272d` の上では、文字 `#e6edf3` が 12.7:1、ラベル `#8a949e`
  が 4.9:1
- `--color-danger` は、ライトテーマの `#d1242f` が `#ffffff` に 5.2:1・
  `#f6f8fa` に 4.9:1・`#eff2f5` に 4.7:1、ダークテーマの `#ff7b72` が `#121417`
  に 7.3:1・`#1a1d21` に 6.7:1・`#23272d` に 6.0:1 で、どれも AA を満たす
- `--color-success`・`--color-warning` は枠と印の色で、文字は
  `--color-foreground` のまま。ライトテーマの `#1a7f37` は `#ffffff` に 5.1:1・
  `#f6f8fa` に 4.8:1、`#9a6700` は 4.9:1・4.6:1。ダークテーマの `#3fb950`・
  `#d29922` は `#121417` に 7.3:1、`#1a1d21` に 6.7:1 で、どれも AA を満たす
- **結果の表示**は、現場の PACS・モダリティの用語にそろえる：撮影の結果は緑の枠で
  「撮影完了：14 画像」、送信は「送信完了：ORTHANC へ 14/14 画像（ジョブ 11）」
  （失敗は赤の枠で「送信失敗：…」）。予約なし・生年月日が空などの注意は黄色の枠で、
  結果とは分けて並べる。枚数は「画像」、送信キューの1件は「ジョブ」、通信の相手は
  「ホスト」と書く
- **ライトテーマのプライマリカラーは `#0969da`。** 白の背景とのコントラスト比は 5.19:1、
  `#f6f8fa` の背景とは 4.88:1、プライマリボタンの白の文字とは 5.19:1 で、どれも AA
  （4.5:1）を満たす
- **ダークテーマのプライマリカラーは `#1f6feb`。** プライマリボタンの背景として、白の文字との
  コントラスト比は 4.63:1（AA を満たす）。`--color-primary-foreground` は両方の
  テーマで `#ffffff`。注意：`#1f6feb` はダークテーマの背景（`#121417` に
  3.98:1、`#1a1d21` に 3.65:1）の上では、文字には使えない（AA の 4.5:1 に
  届かない）。フォーカスリングなど文字以外の図形の色は 3:1 以上が目安で、満たす
- 部品の形：
  - ボタン：高さ 32px（`h-8 px-3`）、角 `rounded-md`、文字 `text-sm`
    `font-medium`、アイコン 16px。種類はプライマリ（`bg-primary`）・枠線
    （`border border-border`）・背景なし（`hover:bg-muted`）の3つ
  - 表：見出しの行は `h-9`・ラベルの色・`font-normal`、セルは `px-2 py-1.5`、
    行の区切り線 `border-b border-border`、hover で `bg-muted/50`
- フォントの名前に商用フォントを書かない

### 10.3 共通の部品

- **ヘッダー**（どのページにも1つ）：左にツールの名前（`dicom-test-generator`、
  太字・値の色）、中央にページの切り替え（ワークリスト・撮影・PACS・設定）、
  右にテーマの切り替え。「Not for Diagnostic Use / 非医療機器」の表示は
  出さない。機能ごとの注意書きは追加しない
- **情報バー**（ヘッダーの下）：自分の AE タイトル・ワークリストの取得先・既定の
  送信先・文字コード（ワークリスト → 画像）を1行で表示する
- **通知**：操作の結果（成功・失敗）を、その操作のボタンの下に表示する。失敗は
  次の操作まで消さずに残す。右上に浮かぶ通知は作らない
- 患者の値の表示：漢字の氏名は 14px・太字・値の色、かなの氏名は 12px・
  ラベルの色、生年月日は `1975/05/10（51歳・男）` の形式。UID は 0.75rem・等幅・
  ラベルの色で、コピーのボタンを付ける

### 10.4 ワークリストの画面

```text
┌ dicom-test-generator  [ワークリスト] 撮影  PACS  設定                                    ┐
│ 自分: DTG_CT01 │ ワークリスト: RIS_TEST │ 送り先: PACS_TEST │ 文字: ISO_IR 192 → ISO_IR 192 │
├──────────────────────────────────────────────────────────────────────┤
│ 予定の日 [今日 ▼]  モダリティ [CT ▼]  装置の AE タイトル [この装置で絞る ▼] │
│ 患者 ID [      ]  氏名 [      ]  受付番号 [      ]   [ワークリストを取得]  │
├──────────────────────────────────────────────────────────────────────┤
│ 時刻  患者 ID   氏名            生年月日・性別        受付番号  検査の記述 │
│ 09:00 P000001  山田 太郎        1980/01/15（45歳・男） A0001    胸部 CT   │
│              やまだ たろう                                            │
│ 09:30 P000002  …                                                      │
├──────────────────────────────────────────────────────────────────────┤
│ 12 件（14:05:31 に取得）                     [選んで撮影へ] [取得し直す] │
└──────────────────────────────────────────────────────────────────────┘
```

- 行を選ぶと、一覧の下に詳細のパネル（予約の値の全部・Study Instance UID・
  Scheduled Procedure Step ID・予定の装置の AE タイトル・文字コード）を表示する。
  予定の装置の AE タイトル（Scheduled Station AE Title (0040,0001)）は、予定日時・
  モダリティとは別の行にする
- 予定日は「今日・明日・日付を指定・絞らない」から選ぶ。範囲は CLI の `--date`
  で取得する。モダリティの欄は空にすると絞り込まない
- 「装置の AE タイトル」の欄は、Scheduled Procedure Step Sequence の中の
  Scheduled Station AE Title (0040,0001) の条件（5.1）。「この装置の AE タイトルで
  絞る（DTG_CT01）」（既定。自分の AE タイトルを入れる）と「絞らない」（長さ 0 で
  送る）から選ぶ
- 条件を戻すボタンと、Requested Procedure ID の欄は無い。ページを開き直せば既定の
  条件に戻る
- ボタンの文言は「ワークリストを取得」「取得し直す」にする（モダリティの画面で
  一般的な言い方。CLI の `worklist query`・`--refresh` の名前は変えない）
- 「取得し直す」は、選んだ予約を受付番号と Requested Procedure ID で再取得し、
  最新の値にする
- 「取得し直す」は、行を選ぶまで押せない（「ワークリストを取得」の直後は、どの行も
  選んでいない）。押せない間は、ボタンの title に「行を選ぶと押せます」を出す。
  押したら応答が返るまで押せない。予約の鍵の無い要求（スクリプトが無効のときなど）
  が届いたら、サーバーは C-FIND を送らずに「予約を選んでから「取得し直す」を
  押してください」と表示する
- 取得し直したら、開いている詳細のパネルも新しい値にする。「ワークリストを取得」で
  一覧を取得し直したときは、詳細のパネルを閉じる
- 取得し直せないとき・撮影の画面で予約が見つからないときは、10.8 の文言を表示する。
  ワークリストの画面では一覧を消さずに残す。内部の予約の鍵と CLI 向けの hint は
  画面に出さない（CLI の文言は変えない）
- 予定の AE タイトルが自分と異なる予約は、行に「別の装置」の印を付ける
- 0 件のとき：「予約はありません。条件を広げるか、緊急の患者で撮ってください」と、
  [緊急の患者で撮る] のボタンを表示する

### 10.5 撮影の画面

```text
┌ 予約の値（読むだけ） ───────────────────────────────────────────┐
│ 患者 ID P000001   氏名 山田^太郎=やまだ^たろう   1980/01/15・男  │
│ 受付番号 A0001   検査の記述 胸部 CT   Study UID 2.25.1234… [⧉]    │
│ ワークリストの文字コード ISO_IR 192                                │
├ 撮影の設定 ─────────────────────────────────────────────────────┤
│ テンプレート [ct_generic ▼]  装置 [なし ▼]  文字コード（画像）[auto ▼] │
│ シリーズ数 [2]  画像数 [1, 20]  異常のデータ [なし ▼]              │
│ 1回の撮影は合計 2000 画像まで。                                   │
│ MPPS：使わない                                                    │
├─────────────────────────────────────────────────────────────────┤
│ [撮影] [撮影して送る]                                              │
└─────────────────────────────────────────────────────────────────┘
```

- 予約の値は入力欄にしない（読み取り専用）。修正したいときは RIS の側で修正して
  「取得し直す」
- テンプレートのモダリティと予約のモダリティが異なれば、[撮影] を押せなくし、
  「予約は MR、テンプレートは CT です」と表示する
- 「装置」は装置プロファイル（[13_device_profiles.md](13_device_profiles.md)）。
  選択するとテンプレートの上に重ねる。プロファイルのモダリティが予約と異なるときも
  同じく停止する
- 緊急の患者：予約なしで開いたときは、患者の値（ID・氏名の英字・漢字・かな・
  生年月日・性別）を入力欄にする。受付番号は空で固定し、「予約なし（受付番号は
  空）」と表示する
- **必須の入力欄**：緊急の患者の「患者 ID」と「氏名（英字）」、撮影の設定の
  「シリーズ数」と「画像数」。欄の名前の横に「必須」の印を付け、空なら送信できない
  ようにする（画面の `required`）。サーバー側でも検証し、空なら撮影せずに停止する
  （`ModalityService` が `ValidationError`。CLI の `exam --emergency` も同じで、
  `--patient-name` の英字の成分グループが空なら終了コード 4）。ほかの欄（漢字・
  かな・生年月日・性別・検査の記述）は空でよい
- **氏名の姓と名の区切り**：利用者は `^` を入力しないので、英字・漢字・かなの3つの
  欄で、空白を `^` に置き換える
  - 置き換え方：前後の空白を除去し、`^` の前後の空白を除去し、連続した空白
    （半角・全角とも）を1つの `^` にする。例「Yamada Taro」→「Yamada^Taro」、
    「山田　太郎」→「山田^太郎」。既に `^` で区切った値はそのまま
  - 画面では欄からフォーカスが外れたとき（blur）に置き換えて表示する（補助）。
    サーバー側（`ModalityService.emergency_person_name`）でも同じ置き換えを行う
    ので、スクリプトが無効でも同じ値になる
  - `=`（成分グループの区切り）と制御文字は、どの欄でも拒否する
    （`ValidationError`）
- **`\` は拒否する**：`\` は DICOM の値の区切り（PS3.5 6.2）で、LO・PN・SH に
  入れると同じ属性の値が複数になり、VM 1 の属性（Patient ID・Patient's Name・
  Study Description）に合わない。緊急の患者の「患者 ID」「氏名」と「検査の記述」に
  `\` があれば、サーバー側（`ModalityService.exam`）で `ValidationError` にして
  撮影しない（画面・CLI とも。CLI は終了コード 4）
  - 一覧・撮影の画面の表示では、`^` を空白にして表示する
- プライマリボタンは [撮影して送る]（既定の送信先へ送信する）。[撮影] は枠線のボタンにし、
  撮影後の結果に [送る] を表示する
- **シリーズ数を変えたときの画像数**：シリーズ数を変えたら、画像数の欄を
  シリーズごとに同じ数で自動入力する（先頭の数を並べる。例：シリーズ数 3・
  画像数 `2` → `2,2,2`）。画像数を手入力で修正した後は上書きしない。CLI の
  `exam -i` を省いたときも、シリーズごとに 1 枚で埋める（`-s 3` なら `1,1,1`）
- **二度押しの防止**：[撮影]・[撮影して送る]・[送る] を押したら、応答が返るまで
  ボタンを押せなくし、処理中の表示（スピナーと「撮影しています」「撮影して
  送っています」「送信しています」）を出す。前の結果は新しいリクエストの前に消す。
  サーバーに届かなかったときは、結果の位置に通知する。サーバー側でも、撮影の
  画面が発行するトークン（`exam_token`）を受け付けた撮影ごとに記録し、同じ
  トークンの撮影は2回受け付けない（撮影中も、撮影後も）。失敗した撮影のトークンは
  戻す。撮影完了の応答が新しいトークンを返すので、続けて別の撮影をするときに画面を
  開き直す必要は無い。トークンの無いリクエスト（スクリプトなど）は受け付ける
- 画面には「病院」「ピクセル」の欄と、進捗バー・取り消しは無い。病院と
  ピクセルは設定の既定値を使い、CLI の `--hospital`・`--pixel-mode` で選択できる。
  作成する画像はテストに必要な分だけで、すぐに終わるため、進捗は表示しない
- **MPPS**：撮影の画面には状態を表示するだけにする（選択する欄と再送のボタンは
  無い。使うかは設定で決め、再送は CLI の `mpps retry`）。撮影の設定の下に
  「MPPS：使う（相手の AE タイトル）」か「MPPS：使わない」を1行で表示する。
  撮影後の結果に、その撮影の MPPS の状態を1行で表示する：「MPPS：COMPLETED を
  送りました」「MPPS：DISCONTINUED を送りました」「MPPS：送れませんでした
  （理由）。`python -m app.cli mpps retry` で再送します」
- 「文字コード」は撮影の設定の欄に置き、設定の既定値を初期値にする
- **1回の撮影の量の上限**（1つのリクエストでディスクを使い切らないため）：
  - 1回の撮影の合計の画像数は、設定 `modality.max_images_per_exam`（既定 2000）
    までにする。`ModalityService.exam` が検証し、超えたら撮影せずに
    `ValidationError`（CLI は終了コード 4）。画面にも上限を表示する
  - 画面では、あわせてシリーズ 99・1シリーズ 1000 画像までにする（入力欄の検証）
  - 同時に実行する撮影は、1つの `ModalityService`（画面のプロセス）の中で1つに
    限る。実行中に来た撮影は待たせずに拒否する（`ModalityError`。「ほかの撮影が
    走っています」）。別々の CLI のプロセスどうしは数えない
  - ディスクの空き容量は確認しない（合計の画像数の上限で抑える）
- 画面から来るテンプレートの名前は、1つのファイル名（英数字・`_`・`-`）だけを
  受け付ける（配置場所の外は読み込まない。Job YAML・CLI も同じ）

### 10.6 PACS の画面

- **送信先の一覧**：名前・AE タイトル・ホスト・ポート・保管確認（Storage Commitment）の有無。各行に
  [C-ECHO] と、押した結果（つながった（○ ms）・つながらない（理由））を表示する
- **送信キューと送信の履歴**：1つの表にまとめる。検査ごとの行（ID・状態・
  送信先・受付番号・送信できた画像数／画像数・時刻・出力フォルダ）。新しい件を
  上にする。状態は 8.2 の「待機中・送信中・送信完了・送信失敗」。失敗の行は理由と
  [再送]。表の上に [失敗をすべて再送]。2 秒ごとに再取得する。出力フォルダは
  コピーのボタンでコピーできる
- **保管確認の結果**：「確認待ち・確認済・確認の失敗・確認の時間切れ」。送信
  キューの表に「保管の確認」の列を1つ追加して表示する（保管確認を使わない送信先の
  件は「—」）。失敗の行には、失敗した画像数か理由（Association を確立できない、
  など）を小さく表示する。再要求のボタンは無い（CLI の `commit --job ID`。8.3.3）
- 次のものは無い：待機中の件の [送る]・[取り消す]（画面から作成した件はすぐ送信
  するので待機中に残らない）、履歴の日付の絞り込み、行の患者の氏名（送信キューは
  氏名を持たない）、送信先ごとの最後の C-ECHO の時刻（押した結果だけをその場に
  表示する）

### 10.9 待ち受けと認証

**既定はループバック（`127.0.0.1`）だけで待ち受け、認証は付けない。** 例外は
1つ：ループバック以外のアドレス（`0.0.0.0` など）で待ち受けるときは、認証を
必須にする（ADR-0011 の決定 5）。

- ループバック以外で待ち受ける設定で、パスワードの設定が無ければ起動しない
  （エラーで停止し、理由を表示する）
- 認証は HTTP Basic（利用者 1 人）。パスワードは環境変数 `DTG_WEB_PASSWORD_FILE`
  が指すファイルから読み込む。既定値を置かない。設定ファイルに平文で書かせない
- 書き込みのリクエスト（POST）は、`Origin` ヘッダー（無ければ `Referer`）の
  ホストとポートが、リクエストの `Host` と同じときだけ受け付ける（ほかのサイトからの
  リクエストを拒否する。どちらも無いリクエストも拒否する）。あわせて、起動のたびに
  作成する CSRF トークンをページに埋め込み、POST のヘッダー `X-CSRF-Token` か
  フォームの項目 `csrf_token` で返させ、一致しなければ拒否する（403）
- ループバック（`127.0.0.1`・`::1`・`localhost`）で待ち受けるときは、`Host`
  ヘッダーがループバックの名前のときだけ受け付ける（DNS rebinding で、ほかのサイトの
  ページからローカルの画面を読み取らせないため）
- `Host`・`Origin`・`Referer` ヘッダーが URL として解析できない（例 `Host: [`）
  ときは、例外にせずに拒否する（`Host` は 400、`Origin`・`Referer` は 403）
- ユーザー名は `dtg`。パスワードのファイルは起動時に1回読み込み、前後の空白と
  改行を除去する。ファイルが無い・読めない・空なら起動しない。
  `DTG_WEB_PASSWORD_FILE` があれば、ループバックで待ち受けるときも認証を付ける
- 応答には `Content-Security-Policy`（同一オリジンのリソースだけを読み込む。
  インラインのスクリプトを使わない）・`X-Content-Type-Options: nosniff`・
  `Referrer-Policy: same-origin`・`X-Frame-Options: DENY` を付ける
- HTTPS には対応しない。ネットワークに公開するときは、前段のリバースプロキシで TLS
  を終端することを README に書く
- テスト用のツールなので、利用者の管理・二要素認証・監査ログは持たない

### 11.4 exam

|-----------|------|-----------|

| `--emergency` | 予約なし。`--patient-*` が必須 | false |
| `-m, --modality NAME` | テンプレート | 設定の既定値 |

| `--send` | 作成した後に既定の送信先へ送信する | false |
| `--to NAME` | `--send` の送信先 | 既定の送信先 |
| `--study-description TEXT` | 検査の記述（`--emergency` のときだけ） | 空 |
| `--patient-id`・`--patient-name` | 緊急の患者の ID・氏名（PN。`--emergency` のとき必須。英字の成分グループは空にできない。10.5） | — |

  に書き出す（受付番号は 6.5 の規則でファイル名に変換する。同じ秒に同じ名前が
  あれば `_2`・`_3` を追加する）。同じ予約で2回撮影すると、別のフォルダに同じ

### 11.5 send・queue

```bash
python -m app.cli send output/modality/A0001_20261018090000/ --to PACS_TEST
python -m app.cli queue list --status failed
python -m app.cli queue retry --all
python -m app.cli queue retry --job 3
python -m app.cli queue retry --stale
```

- `send FOLDER`：フォルダの `*.dcm` を送信キューに1件（1つの検査）として入れ、
  すぐに送信する。`--to` が無ければ既定の送信先
- `queue list`：`--status` は `pending`（待機中）・`sending`（送信中）・
  `sent`（送信完了）・`failed`（送信失敗）。`--json` で JSON
- `queue list`：停止した送信中（8.2）の件には `[STALE]` を付ける。`--json` では
  `stale` が `true`
- `queue retry`：`--all`（失敗のすべて）・`--job ID`・`--stale`（停止した送信中の
  すべて。失敗に戻してから送信する）のどれか1つを必須にする。失敗したファイル
  だけを再送する
- `queue list`：保管確認の状態を `COMMIT` の列に出力する（`waiting`・`confirmed`・
  `failed`・`timed_out`。使わない件は `-`）。`--json` では `commitment`
  （使わない件は空文字列）と `commitment_error`

### 11.6 終了コード

通信の失敗（Association を確立できない・拒否された・相手が Failure を返した・
タイムアウト）は 5 にする。[04_cli.md](04_cli.md) の表も同じ。

| コード | 意味 | この章で起きる例 |
|-------|------|------------------|
| 0 | 成功 | — |
| 1 | 一般エラー | 作成の失敗 |
| 2 | 設定エラー | `modality:` の節のエラー（`ModalityConfigError`） |
| 3 | I/O エラー | 出力フォルダに書き込めない |
| 4 | バリデーションエラー | 予約の値を転記できない（`WorklistMappingError`）・表現できない文字 |
| 5 | 通信エラー | `AssociationError`・`WorklistQueryError`・`StoreError`・`StorageCommitmentError`（`commit` が確認済にならない）・`MPPSError`（`mpps retry` で送信できない分が残る） |

- 結果は標準出力、エラーは標準エラー出力
- `--json` のときは標準出力に JSON だけを出力する

### 11.7 相手から来る値を端末に出力するとき

**ワークリストの値（氏名・記述など、相手から来る値）は、端末に出力する前に制御文字を
可視化する。** 例外は無い。ESC・CSI・OSC などをそのまま出力すると、端末の表示や
タイトルを書き換えられるため。

- 置き換える文字：C0（U+0000〜U+001F）・DEL（U+007F）・C1（U+0080〜U+009F）・
  Unicode の双方向制御文字（U+061C・U+200E・U+200F・U+202A〜U+202E・U+2066〜
  U+2069）・行と段落の区切り（U+2028・U+2029）
- 通常の出力：`\x1b`・`‮` のような可視の形にする（`app/cli/terminal.py` の
  `sanitize_for_terminal`）。標準エラー出力のエラーメッセージも同じ
- `--json`：同じ文字を JSON の `\uXXXX` に変換する（`json_for_terminal`）。
  デコードすると元の値に戻る（値そのものは変えない）
- ログに相手から来る値を出力するときは `%r` で出力する（制御文字がエスケープ
  される）。Patient ID も相手から来る値として扱う
- 端末（標準エラー出力）に出すログは、整形した後の文字列を行ごとに
  `sanitize_for_terminal` で処理する（改行は残す。例外の Traceback も同じ）。
  ファイルのログはそのまま

### 11.8 commit

```bash
python -m app.cli commit --job 3
python -m app.cli commit --job 3 --wait 60 --json
```

| オプション | 説明 | デフォルト |
|-----------|------|-----------|
| `--job ID` | 送信キューの ID（必須。状態が送信完了の件だけ） | — |
| `--wait SECONDS` | 結果を待つ秒数（1 以上） | 送信先の `commitment_timeout_seconds` |

- 送信先が保管確認を使わない（`storage_commitment: false`）なら、送信せずに
  終了コード 2 で停止する
- 待ち受け（`modality.listen`）を起動してから N-ACTION を送信し、結果か `--wait`
  の秒数まで待つ。待ち受けを起動できない（ポートが使用中）ときは、送信せずに
  終了コード 2 で停止し、画面が動いていないかを確認するよう表示する
- 結果が確認済なら終了コード 0。確認の失敗、または `--wait` の間に来ない（状態は
  確認待ちのまま。時間切れはキューが判定する）なら終了コード 5
- 出力は件の ID・状態・確認できた画像数／要求した画像数。`--json` では `job_id`・
  `transaction_uid`・`status`・`num_requested`・`num_confirmed`・`num_failed`・
  `error`

### 11.9 mpps

```bash
python -m app.cli mpps list
python -m app.cli mpps list --json
python -m app.cli mpps retry
```

- `mpps list`：MPPS の通知のキューを出力する（ID・MPPS の状態 `IN PROGRESS`・
  `COMPLETED`・`DISCONTINUED`・送信できたか・受付番号・時刻・失敗の理由）。
  `--json` で JSON
- `mpps retry`：未送信の通知を、古い順に再送する（8.4.1）。MPPS を使わない設定で、
  未送信の通知も無いなら終了コード 2。送信できない分が残れば終了コード 5
