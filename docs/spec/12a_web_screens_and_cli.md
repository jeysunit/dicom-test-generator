# 12a. モダリティエミュレーター：Web 画面と CLI

この文書は、モダリティエミュレーターのうち利用者が操作する部分（Web 画面と CLI）を
定める。通信・予約の値の転記・送信・モジュールと配置・設定・ログは
[12_modality_emulator.md](12_modality_emulator.md) にある。

章番号は spec/12 から続けて振っている。この文書は 10 章（Web 画面）と 11 章
（CLI）を持つ。本文の「5.5」「8.3.3」のような番号だけの参照は spec/12 の章を
指す。

設計の判断：[ADR-0011](../decisions/0011-modality-emulator.md)

---

## 10. Web 画面

### 画面の方針

**画面はすっきりさせる。余白を取り、部品を少なくし、一画面で行う操作を1つに
する。** クラウド型の電子カルテのような、余白の多い落ち着いた画面を目安にする。
例外は無い。

- DTG は診療のためではなく、システムのテストでモダリティの代わりに使う。技師の
  操作をすべて再現する必要は無く、テストに必要な「取得→選択→撮影→送信→確認」を
  迷わず実行できればよい
- **機能は追加するより減らす。** 画面に何かを追加したくなったら、まずテストに必要
  かを検討する。不要なら追加しない。CLI か設定ファイルでできることは、画面に
  出さなくてよい
- 一画面のプライマリボタンは1つにする（例：ワークリストは「選んで撮影へ」、撮影は
  「撮影して送信」）。ほかの操作は枠線のボタンか背景の無いボタンにして目立たない
  ようにする
- 詳しい値（予約の値の全部・UID など）は最初から並べず、開いて表示する
  （パネル・折りたたみ）

### 10.1 技術

**画面は、サーバー側で描画する Web 画面（FastAPI・Jinja2・HTMX・Tailwind CSS の
standalone の実行ファイル）にする。** 選んだ理由は ADR-0011 にある。

- Node は不要。Tailwind CSS v4 は standalone の実行ファイル（GitHub の
  releases に OS ごとの実行ファイルと `sha256sums.txt` がある）で CSS を作成できる。
  バージョンを固定し、sha256 を検証してから使う
- 作成した CSS（`app/web/static/app.css`）は commit する。利用者は Tailwind の
  実行ファイル無しで動かせる
- htmx は1つの JavaScript のファイルを `app/web/static/` に置く（バージョンを固定
  し、入手元と sha256 を [development.md](../development.md) の 5 章に書く）。外部の
  CDN からは読み込まない。ネットワークに接続しない環境でも動かすため
- アイコンは Lucide（ISC License）の SVG を、使う分だけ `app/web/static/icons/`
  に置く。ライセンスの文を同じ場所に置く
- Python のパッケージは `fastapi`・`uvicorn`・`jinja2`・`python-multipart`
  （フォーム）、テスト用に `httpx`（FastAPI の TestClient が使う）
- 画面の更新（送信キューの状態など）は HTMX の定期的な取得
  （`hx-trigger="every 2s"`）で行う。SSE・WebSocket は使わない
- 色・文字の値と部品の CSS は、3 製品で共通の ui-kit の写しを読む
  （`app/web/static/ui-kit/` の `tokens.css`・`components.css`、版は同じ場所の
  `VERSION`）。`base.html` で tokens.css → components.css → app.css の順に読む。
  写しは DTG の側で直さず、版が上がったら同じ版の写しに替える
- 入力の CSS（`app/web/styles/input.css`）は、テンプレートに書く Tailwind の色の名前
  （`bg-surface`・`text-label` など）を `@theme inline` で tokens.css の変数へつなぐ
  ことと、ui-kit に無い DTG だけの部品（ルーチンの表・UID のコピー・アイコンなど）
  だけを持つ。ui-kit と同じ名前の部品は書かない
- tokens.css の値が 10.2 の表とずれたら検出できるよう、テストで比較する
  （`tests/web/test_theme_tokens.py`）

### 10.2 見た目の基準

**画面（ワークリスト・撮影・PACS・設定）は、ライトテーマを初期設定にし、
ダークテーマにも切り替えられる。** 例外は1つ：画像のサムネイルを並べる部分だけ、
周囲をダークテーマにする。

- これらは文字を読む画面である。日本の医療機関で広く使われている画面でも、画像を
  見る画面は暗い背景、一覧や事務の画面は明るい背景が多い
- テーマの切り替えはヘッダーのボタンで行い、ブラウザの `localStorage` に
  保存する。保存されていなければライトテーマ
- どちらのテーマでも、基準の文字は 14px（0.875rem）・行間 1.5。表の行・入力欄も
  14px を下回らない（補足の文字だけ 12px）
- 余白は 3 製品共通のトークンにそろえる（tsunagi-dicom の `docs/design-system` の
  tokens.md）：区画の間は 12px、区画の中の入力欄の間は 12px 以上、ページの左右は
  16px 以上（幅 768px 以上は 24px）。1画面に詰め込まず、詳細は区画を開いて表示する
- 文字と背景のコントラスト比は WCAG 2.2 の AA（4.5:1）以上にする

- `--color-success`・`--color-warning` は枠と印の色で、文字は

- 入力欄・ボタンの輪郭 `--color-border-input`（`#7a7a7a`・ダークテーマ `#8a8a8a`）は、
  背景との対比が 3:1 以上（`#ffffff` に 4.3:1・`#1b1b1b` に 5.0:1）。区切りの線の
  `--color-border` は飾りで、この対比は求めない
- アクセントの色（primary・link）は、選択・プライマリボタン・リンク・フォーカスリング
  にだけ使い、状態の意味（正常・注意・異常）には使わない。状態の色（danger・success・
  warning）は別の枠で持ち、値は前のまま
- **結果の表示**は、現場の PACS・モダリティの用語にそろえる：撮影の結果は緑の枠で

  結果とは分けて並べる。枚数は「画像」、送信キューの1件は「ジョブ」、通信の相手は
  「ホスト」と書く

- **ダークテーマのプライマリカラーも `#4b4fbf`。** プライマリボタンの背景として、白の文字との
  コントラスト比は 6.62:1（AA を満たす）。`--color-primary-foreground` は両方の
  テーマで `#ffffff`。注意：`#4b4fbf` はダークテーマの背景（`#1b1b1b` に
  2.60:1、`#242424` に 2.34:1）の上では、文字にも枠にも使えない。そのため、
  ダークテーマの文字・フォーカスリングには、別に持つ `--color-link`・`--color-ring`
  （`#a5a8ff`。`#1b1b1b` に 7.91:1、`#242424` に 7.13:1）を使う
- 部品の形は ui-kit の components.css のとおり：
  - ボタン：高さ 32px（`.btn-sm` 28px、表の行の中 24px）、角 4px、アイコン 16px。
    種類はプライマリ（`.btn-primary`）・枠（`.btn`。枠は `--color-border-input`）・
    枠なし（`.btn-ghost`）・危険（`.btn-danger`）
  - 表（`.tbl`、`.tbl-wrap` で包む）：行 28px、見出しの行は 28px・地 `surface`・
    ラベルの色・`font-normal`・表の中をスクロールしても残る。行の区切り線は
    `--color-border`、hover で `muted`
- フォントの名前に商用フォントを書かない

### 10.3 共通の部品

- **外枠**（どのページも同じ。3 製品共通の決まりは tsunagi-dicom の
  `docs/design-system` の menu.md・screen-types.md）：上に帯（高さ 48px）、その下は、
  左にナビ（幅 208px）、右に本文。帯の下に別の帯（情報バー）は置かない。ページへの
  入り口は左のナビだけに置き、上の帯にはタブを置かない。本文は左寄せで、幅は画面の
  型ごとに 1 つ（一覧の画面は幅いっぱい、撮影は最大 900px、設定は最大 560px）

  ```text
  ┌ dicom-test-generator                      [接続の状態 ✓接続中] [表示] ┐
  ├────────────┬─────────────────────────────────────────────────────┤
  │ 業務       │                                                     │
  │ ▌ワークリスト │  本文（10.4〜10.7）                                 │
  │   撮影     │                                                     │
  │ 接続       │                                                     │
  │   PACS     │                                                     │
  │ 管理       │                                                     │
  │   設定     │                                                     │
  └────────────┴─────────────────────────────────────────────────────┘
  ```

- **ヘッダー**（どのページにも1つ）：左にナビの開閉のボタンとツールの名前
  （`dicom-test-generator`、太字・値の色）、右に接続の状態とテーマの切り替え。
  「Not for Diagnostic Use / 非医療機器」の表示は出さない。機能ごとの注意書きは追加しない
- **左のナビ**：群は「業務」（ワークリスト・撮影）・「接続」（PACS）・「管理」（設定）。
  項目は絵（Lucide の list・camera・server・settings）と名前で、名前は各ページの題と
  同じにする。現在のページは、`--color-selected` の地・左の
  3px の線（`--color-ring`）・太字で示し、`aria-current="page"` を付ける（色だけに
  しない）。ヘッダーのボタンで閉じると幅 56px の絵だけになり（名前は `title` に持つ）、
  開閉はブラウザの `localStorage` に覚える。幅が 768px 未満のときは、ナビを本文の上に
  1 行で並べ、群の名前は省く。新しいページの項目は、上の帯に足さず、このナビに足す
- **接続の状態**（ヘッダーの右）：閉じているときは、全体の状態を 1 つの札で出す。
  ワークリストの検索と各送信先の接続確認の最後の結果が全部成功なら「接続中」、1 つでも
  失敗なら「一部が接続不可」（失敗の札）、まだ試していなければ「未確認」。最後の結果は
  画面を動かしている間だけ覚え、保存しない。押すと、標準の `popover` で中身が出る（外を
  押す・Esc で閉じる）。中身は、自分の AEタイトル・ワークリストの取得先（札と時刻）・
  送信先ごとの名前（標準に「標準」の札）・札・時刻・文字コード（ワークリスト → 画像）と、
  下の「接続確認」「PACS を開く」。「接続確認」（`POST /link/check`）は、ワークリストの
  取得先とすべての送信先に C-ECHO を送り、結果で中身と札を差し替えて、中身を開いたままに
  する。確かめている最中にもう一度届いたら、重ねて送らず何も差し替えない（204）。
  「PACS を開く」は、送信先ごとの接続確認と送信ジョブのある PACS の画面への道で、
  ページへの入り口（左のナビ）とは別に、この中身にだけ置く。ワークリストの検索と接続確認の
  応答が、札と中身を同じ応答で差し替える。上の帯の下に別の帯（情報バー）は置かない
- **装置の切り替え**（ADR-0023）：設定に装置が2台以上あれば、接続の状態の中身の「自分」の
  代わりに「装置」の選択（CT1（DTG_CT01）▼）を出す。選ぶとすぐに切り替え、ページを
  読み込み直す。撮影・送信の最中は切り替えず、中身に「撮影・送信の最中は装置を
  切り替えられません」と出して（閉じていれば開き直して）元の装置に戻す。サーバーに届かなかったとき・断られた
  とき（403 など）も、選択を元の装置に戻して中身に理由を出す。装置が1台なら
  「自分」の行に AEタイトルを出すだけ
- 送信ジョブの詳細（10.6）に「名乗る AEタイトル」（件を作ったときの装置の AE
  タイトル。再送信もこれで名乗る）を出す
- **通知**：操作の結果（成功・失敗）を、その操作のボタンの下に表示する。失敗は
  次の操作まで消さずに残す。右上に浮かぶ通知は作らない。通知（知らせ）は、左に 4px の
  状態の色、印と文字で出し、文字は本文の色のままにする
- 患者の値の表示：漢字の氏名は 14px・太字・値の色、かなの氏名は 12px・
  ラベルの色、生年月日は `1975/05/10（51歳・男）` の形式。UID は 0.75rem・等幅・
  ラベルの色で、コピーのボタンを付ける

  Scheduled Procedure Step ID・予定の装置の AEタイトル・文字コード）を表示する。
  予定の装置の AEタイトル（Scheduled Station AE Title (0040,0001)）は、予定日時・
  モダリティとは別の行にする。Requesting Physician (0032,1032) は「依頼医」、
  Referring Physician's Name (0008,0090) は「紹介医」として別の行に出す。患者の
  「氏名」も同じ形で出す（`^` は空白、成分グループは ` / ` で区切り、一覧の氏名と同じ
  漢字・かな・英字の順にする。空なら「—」）
- 予定日は「今日・明日・日付を指定・絞らない」から選ぶ。範囲は CLI の `--date`
  で取得する。モダリティの欄は空にすると絞り込まない
- 「装置の AEタイトル」の欄は、Scheduled Procedure Step Sequence の中の
  Scheduled Station AE Title (0040,0001) の条件（5.1）。「この装置で絞る
  （DTG_CT01）」（標準。接続の状態で選んだ装置の AEタイトルを入れる）と「絞らない」（長さ 0 で
  送る）から選ぶ。選択肢は、幅の狭い画面でも括弧の AEタイトルまで見える長さにする
- 条件を戻すボタンと、Requested Procedure ID の欄は無い。ページを開き直せば初期設定の
  条件に戻る
- ボタンの文言は「ワークリスト検索」「再検索」にする（モダリティの画面で
  一般的な言い方。CLI の `worklist query`・`--refresh` の名前は変えない）
- 取得の時刻は、画面を動かすマシンの時刻に、UTC からの差を添えて「（2026-10-23
  08:03:44 UTC+09:00 に取得）」の形で出す（画面に出す時刻のタイムゾーンが読めるように。
  PACS の画面の時刻の見出しも同じ。10.6）
- 「再検索」は、選んだ予約を受付番号と Requested Procedure ID で再取得し、
  最新の値にする
- 「再検索」は、行を選ぶまで押せない（「ワークリスト検索」の直後は、どの行も
  選んでいない）。押せない間は、ボタンの title に「行を選ぶと押せます」を出す。
  押したら応答が返るまで押せない。予約の鍵の無い要求（スクリプトが無効のときなど）
  が届いたら、サーバーは C-FIND を送らずに「予約を選んでから「再検索」を
  押してください」と表示する
- 再検索したら、開いている詳細のパネルも新しい値にする。「ワークリスト検索」で
  一覧を再検索したときは、詳細のパネルを閉じる
- 再検索できないとき・撮影の画面で予約が見つからないときは、10.8 の文言を表示する。
  ワークリストの画面では一覧を消さずに残す。内部の予約の鍵と CLI 向けの hint は
  画面に出さない（CLI の文言は変えない）
- 予定の AEタイトルが自分と異なる予約は、行に「別の装置」の印を付ける
- 撮影済みの予約（12 の 6.3）は、行と予約の詳細に「撮影済み」の印を付ける
- 行の印（撮影済み・別の装置）は氏名の下に出す。印は状態の札（知らせ ◇。枠・印・文字）にする。
  氏名の列は狭い幅でも潰さず（最小の
  幅を持たせる）、幅 390px でも横にスクロールせずに印が見える
- 0 件のとき：空の状態として、1 行目に事実「予約はありません。」、2 行目に次の手「条件を
  広げるか、緊急の患者で撮ってください」と、[緊急の患者で撮る] のボタンを表示する
  （CLI の文言は 1 文のまま変えない）
- 画面の形：見出しの行（題「ワークリスト」）の下に、検索の帯（条件の欄。地は muted-strong、
  項目名は欄の上に小さく出す。折り返してよい）、一覧を置く。一覧の上に件数の行（「n 件（取得の
  時刻）」）を置く。一覧と詳細の並べ方（型 A か型 B か）は、画面の決まりの判断を待つ

### 10.5 撮影の画面

画面の型 C（入力）の形にする（3 製品共通の決まりは tsunagi-dicom の
`docs/design-system` の screen-types.md・components.md）。上から、パンくず（予約から
撮るときだけ。ワークリスト / 氏名 / 撮影）、見出しの行（題「撮影」）、画面の上の知らせ、
患者バナー、区画、操作の行の順で、幅は最大 900px。区画の見出しは 14px の太字で、
区画の間は 12px にする。必須の項目は項目名の横に「必須」と書く。

```text
ワークリスト / 山田 太郎 / 撮影
撮影
┌ 山田 太郎 ─ 患者ID ─ 生年月日・性別 ─ 受付番号 ─ 検査名 ─ [予約の値（読むだけ）] ┐
├ 予約の情報 ─────────────────────────────────────────────────────┤
│ 予約のモダリティ CT   Study Instance UID 2.25.1234… [⧉]           │
│ ワークリストの文字コード ISO_IR 192                                │
├ 撮影の設定 ─────────────────────────────────────────────────────┤
│ テンプレート [ct_generic ▼]  装置 [なし ▼]  文字コード（画像）[auto ▼] │
│ 異常のデータ [なし ▼]  ルーチン [胸部 単純 ▼]                      │
│ シリーズ  Series Description  種類        画像数                   │
│ 1         Scout               位置決め    [1]    [外す]            │
│ 2         Mediastinum 5mm     軸位        [60]   [外す]            │
│ …                                                                 │
│ 6         Dose Report         線量の画面  [1]    [外す]            │
│ 1回の撮影は合計 2000 画像まで。                                   │
│ MPPS：使わない                                                    │
├ 操作の行（区画の下に続ける。右端に副 → 主） ───────────────────┤
│ [撮影] [撮影して送信]                                              │
├ 結果（撮影したあと。知らせ・UID・送信の結果） ─────────────────┤
└─────────────────────────────────────────────────────────────────┘
```

- 予約の値は入力欄にしない（読み取り専用）。修正したいときは RIS の側で修正して
  「再検索」
- テンプレートのモダリティと予約のモダリティが異なれば、[撮影] を押せなくし、
  「予約は MR、テンプレートは CT です」と表示する
- 「装置」は装置プロファイル（[13_device_profiles.md](13_device_profiles.md)）。
  選択するとテンプレートの上に重ねる。プロファイルのモダリティが予約と異なるときも
  同じく停止する
- 緊急の患者：予約なしで開いたときは、患者の値（ID・氏名の英字・漢字・かな・
  生年月日・性別）を入力欄にする。受付番号は空で固定し、「予約なし（受付番号は
  空）」と表示する
- 緊急の患者の入力の確かめ：画面（`app/web/static/app.js`）は入力のたびに確かめ、
  誤りの文を欄（label）の中の下に 1 行（`.msg`：印と文）出す。欄は `aria-invalid` と
  `aria-describedby` で結ぶ。欄の下の文は読み上げない（画面の上の知らせだけが
  `role="alert"`）。form は `novalidate` で、ブラウザの検証の吹き出しは使わない。送る前に
  全欄（数の欄を含む）を確かめ、誤りがあれば送らずに、画面の上に誤りの件数の知らせ
  （`role="alert"`）を出して最初の誤りの欄へ移る。サーバーで断った誤りも、その欄の下に結ぶ
  （`FieldValidationError.field`）。欄を直したとき（確かめの無い性別・検査名の欄を含む）と、
  次に送るときに、結んだ誤りの文を消す。サーバー（画面の `POST /exam`・CLI の
  `exam --emergency`・サービス）は同じ規則と同じ文で断る（`app/core/patient_input.py`）。
  文には入れた値を出さない。追加撮影（`--append`）は患者の値を確かめず、前の撮影と
  患者ID・氏名が一致するかで確かめる（以前に受け付けた値の患者にも追加撮影できる）。
  患者ID の欄は撮影の画面を開いたときの先頭の欄（`autofocus`）。規則は次のとおり
  - 患者ID：64 字まで（LO）。基本の文字集合の表示できる字で、`\` と HL7 v2
    の区切り（`^ ~ & |`）は使えない。前後の空白も断る
  - 氏名：1つの群は 64 字まで、成分は 5 つまで。`=`・`\`・制御文字は使えない（PS3.5 6.2）
    - 英字の群：半角の英字・空白（`^` に置き換える）・ハイフン・アポストロフィだけ。
      全角や日本語は断る。英字の群は必須
    - 漢字の群：画像の文字コードで表せる字だけ。UTF-8（`auto` の既定を含む）なら
      `髙橋`・`山﨑` も受ける。`jis`・`jis_kana` のときだけ、表せない字を「この文字コード
      では表せない字があります」の形で断る。半角カナは、`jis_kana` が符号化できても、
      `jis`・`jis_kana` のどちらでも断る（UTF-8 なら受ける）。画面は JIS のときだけ、
      JIS X 0208 の全字を含む範囲で確かめ、最後の判定はサーバーが行う。文字コードの選択を
      変えたら確かめ直す
    - かなの群：全角カタカナ（長音「ー」・中点・空白を含む）だけ。ひらがなは受けて
      カタカナに直し、直したことを欄の下に知らせる（画面は欄から離れたとき、CLI と
      サーバーは受けたとき）。半角カナ・ひらがな以外の字は断る
    - 試験の形（設定 `modality.patient_input_test_mode`、既定は `false`）：かなの群を
      確かめず、直さず、そのまま DICOM に出す（半角カナ・ひらがな・混ざった値の
      受け側の試験用）。長さと禁止の字は見る。画面は欄の下に今の形（「かなの確かめ：
      全角カタカナ」か「試験の形」）を示す
  - 生年月日：暦にある YYYYMMDD で、今日以前。性別：M・F・O か空。「今日」は、サーバーの
    OS の時計の地域ではなく、設定 `modality.timezone`（既定 `Asia/Tokyo`）の日付で決める。
    撮影の検査日・検査時刻も同じ時計（UTC のコンテナで、今日生まれの患者の検査日が生年月日
    より前にならないようにする）。画面は、画面を開いたときのサーバーの今日と、ブラウザの現地の今日の進んでいるほうまでを
    通し、サーバーより先に止めない（最後の判定はサーバーが行う）
  - 検査名：64 字まで、`\` と制御文字は使えない
- **撮影のルーチン**（[ADR-0025](../decisions/0025-exam-routines.md)）：画面を開くと、
  「ルーチン」に予約に当てたルーチンが選ばれ、シリーズの行（番号・Series
  Description・種類・画像数の欄・[外す]）に標準の画像数が入っている。何も変えずに
  [撮影] を押せば、そのルーチンの並びと枚数で撮る
  - 当て方：Requested Procedure Description、Scheduled Procedure Step Description、
    Body Part Examined の順に、ルーチンの見出しの言葉（`keywords`）が含まれるかを見る。
    先の欄で当たれば後の欄は見ない。1つの欄では長い語、同じ長さなら前に出てくる語。
    NFKC で正規化し、大文字と小文字を区別しない。当たらなければモダリティの標準の
    ルーチン（CT は胸部 単純）。緊急の患者はテンプレートのモダリティの標準
  - 選択肢は予約（緊急の患者はテンプレート）のモダリティのルーチンと、最後の
    「手で入れる」。ルーチンを選び直すか、テンプレートを変えると、行を描き直す
    （テンプレートを変えたときは当て直す）
  - 画像数は 1〜1000。範囲の外なら「Lung 1mm の画像数は 1〜1000 にしてください」の
    ようにシリーズの名前で知らせる
  - [外す] を押すと、その行は撮影の対象から外れる。行は消さずに薄く打ち消し線を付けて
    表示し、画像数の欄を押せなくし、ボタンを [戻す] に替える。[戻す] を押すと、外す前の
    画像数のまま対象に戻る。フォーカスは押したボタンに残る。撮影の対象の最後の1行は
    外せない（[外す] を `aria-disabled` にして押しても動かさず、title と見えない文
    「最後の1行は外せません」を `aria-describedby` で結ぶ。`disabled` にしないのは、
    Tab で止まらず、キーボードとタッチで理由が分からないため）。ルーチンの表は、幅 390px
    前後の画面でも枠の中で横にはみ出さない幅にする（右端のボタンを押したときに表が
    動かない）。そのため、狭い画面では「種類」の列を出さず、Series Description の下に
    小さく出す（広い画面は今までどおり列にする）。ルーチンを選び直すか
    テンプレートを変えると、外した行も含めて全部の行が標準の画像数で対象に戻る
  - 撮影の要求を送ってから応答が返るまでは、ルーチンの欄（選択・画像数・[外す]・
    [戻す]）を操作できない
  - 描き直した後は、ルーチンの選択にフォーカスを戻す。描き直しが断られたか届かなかった
    ときは、選択のそばに「ルーチンを切り替えられませんでした。ページを読み込み直してから、
    もう一度選んでください」（届かなかったときは「サーバーに届きませんでした。…」）と
    出し、描き直せるまで撮影の要求を送らない（選んだルーチンと行がずれたまま撮らない）
  - ルーチンを読めない（YAML の誤りなど）ときは「手で入れる」にし、「ルーチンを
    読めません：（理由）」を出す
  - 「手で入れる」を選ぶと、今の「シリーズ数」「画像数」の欄になる
  - ルーチンの欄の無い要求（スクリプトなど）は、手で入れた値で撮る。`routine=auto`
    で行の欄が無ければ、当てたルーチンの全部を標準の数で撮る
- **必須の入力欄**：緊急の患者の「患者ID」と「氏名（英字）」、「手で入れる」の
  「シリーズ数」と「画像数」。欄の名前の横に「必須」の印を付け、空なら送信できない
  ようにする（画面の `required`）。サーバー側でも検証し、空なら撮影せずに停止する
  （`ModalityService` が `ValidationError`。CLI の `exam --emergency` も同じで、
  `--patient-name` の英字の成分グループが空なら終了コード 4）。ほかの欄（漢字・
  かな・生年月日・性別・検査名）は空でよい
- **氏名の姓と名の区切り**：利用者は `^` を入力しないので、英字・漢字・かなの3つの
  欄で、空白を `^` に置き換える
  - 置き換え方：前後の空白を除去し、`^` の前後の空白を除去し、連続した空白
    （半角・全角とも）を1つの `^` にする。例「Yamada Taro」→「Yamada^Taro」、
    「山田　太郎」→「山田^太郎」。既に `^` で区切った値はそのまま
  - 画面では欄からフォーカスが外れたとき（blur）に置き換えて表示する（補助）。
    サーバー側（`ModalityService.emergency_person_name`）でも同じ置き換えを行う
    ので、スクリプトが無効でも同じ値になる
  - `=`（成分グループの区切り）と制御文字は、どの欄でも拒否する
    （`ValidationError`）
- **`\` は拒否する**：`\` は DICOM の値の区切り（PS3.5 6.2）で、LO・PN・SH に
  入れると同じ属性の値が複数になり、VM 1 の属性（Patient ID・Patient's Name・
  Study Description）に合わない。緊急の患者の「患者ID」「氏名」と「検査名」に
  `\` があれば、サーバー側（`ModalityService.exam`）で `ValidationError` にして
  撮影しない（画面・CLI とも。CLI は終了コード 4）
  - 一覧・撮影の画面の表示では、`^` を空白にして表示する
- プライマリボタンは [撮影して送信]（標準の送信先へ送信する）。[撮影] は枠線のボタンにし、
  撮影後の結果に [送信] を表示する
- **撮影済みの予約**（12 の 6.3・ADR-0024）：予約で撮影を終えたら、[撮影]・[撮影して
  送信] を押せなくする（撮影の結果と一緒にボタンを描き直す。開き直しても同じ。押せない
  ボタンには、理由の文への aria-describedby と title「撮影済みの予約は押せません。続けて
  撮るときは「追加撮影」」（`new_order` は「…撮り直しの予約が要ります」）を付ける）。
  `retake_mode: append` なら「撮影済み。続けて撮るときは「追加撮影」」と [追加撮影]
  （プライマリ）を出す。追加撮影の結果にも [送信] を表示する。`new_order` なら [追加
  撮影] を出さず、「撮影済み。撮り直しの予約が要ります（RIS で新しい予約を作って
  ください）」と出す
- 送信の結果を表示した後は、その下に [もう一度送る]（枠線のボタン）を表示する。
  何回でも押せ、押すたびに同じフォルダの画像を標準の送信先へ新しい件として送信する
  （画像は作り直さない。12 の 8.2）
- **シリーズ数を変えたときの画像数**：シリーズ数を変えたら、画像数の欄を
  シリーズごとに同じ数で自動入力する（先頭の数を並べる。例：シリーズ数 3・
  画像数 `2` → `2,2,2`）。画像数を手入力で修正した後は上書きしない。CLI の
  `exam -s` だけを指定したときも、シリーズごとに 1 枚で埋める（`-s 3` なら `1,1,1`）
- **数の欄の検証の文言**：画像数とシリーズ数の欄に範囲の外の値や空の値を入れて押したときは、
  ブラウザの言語に従う文言ではなく、日本語で「Scout の画像数は 1〜1000 で入れてください」
  「シリーズ数を入れてください」と出す（範囲は欄の最小・最大から読む。`app.js`）。form は
  `novalidate` なので、送る前に `app.js` が数の欄を確かめ、誤りがあれば送らずにその欄へ
  移り、文を欄の外の 1 行（ルーチンの区画の末尾）に出す。直したら消す。サーバー側の
  検証は変えない
- **二度押しの防止**：[撮影]・[撮影して送信]・[送信]・[もう一度送る] を押したら、応答が返るまで
  ボタンを押せなくし、処理中の表示（スピナーと「撮影しています」「撮影して
  送信しています」「送信しています」）を出す。前の結果は新しいリクエストの前に消す。
  撮影の応答が返ったら、フォーカスを結果の場所（`#result`、`tabindex="-1"`）へ移す
  （押したボタンは応答まで押せず、フォーカスが本文の先頭へ落ちるため。応答を待つ間に
  別の欄へ移って入力しているときは、フォーカスを奪わない）。
  サーバーに届かなかったときは、結果の位置に通知する。サーバー側でも、撮影の
  画面が発行するトークン（`exam_token`）を受け付けた撮影ごとに記録し、同じ
  トークンの撮影は2回受け付けない（撮影中も、撮影後も）。失敗した撮影のトークンは
  戻す。撮影完了の応答が新しいトークンを返すので、続けて別の撮影をするときに画面を
  開き直す必要は無い。トークンの無いリクエスト（スクリプトなど）は受け付ける
- 画面には「病院」「ピクセル」の欄と、進捗バー・取り消しは無い。病院と
  ピクセルは設定の初期値を使い、CLI の `--hospital`・`--pixel-mode` で選択できる。
  作成する画像はテストに必要な分だけで、すぐに終わるため、進捗は表示しない
- **MPPS**：撮影の画面には状態を表示するだけにする（選択する欄と再送信のボタンは
  無い。使うかは設定で決め、再送信は CLI の `mpps retry`）。撮影の設定の下に
  「MPPS：使う（相手の AEタイトル）」か「MPPS：使わない」を1行で表示する。
  撮影後の結果に、その撮影の MPPS の状態を1行で表示する：「MPPS：COMPLETED を
  送信しました」「MPPS：DISCONTINUED を送信しました」「注意：MPPS の送信に失敗
  しました（理由）。`python -m app.cli mpps retry` で再送信できます」
- 「文字コード」は撮影の設定の欄に置き、設定の初期値を使う
- **1回の撮影の量の上限**（1つのリクエストでディスクを使い切らないため）：
  - 1回の撮影の合計の画像数は、設定 `modality.max_images_per_exam`（初期設定 2000）
    までにする。`ModalityService.exam` が検証し、超えたら撮影せずに
    `ValidationError`（CLI は終了コード 4）。画面にも上限を表示する
  - 画面では、あわせてシリーズ 99・1シリーズ 1000 画像までにする（入力欄の検証）
  - 同時に実行する撮影は、1つの `ModalityService`（画面のプロセス）の中で1つに
    限る。実行中に来た撮影は待たせずに拒否する（`ModalityError`。「ほかの撮影が
    走っています」）。別々の CLI のプロセスどうしは数えない
  - ディスクの空き容量は確認しない（合計の画像数の上限で抑える）
- 画面から来るテンプレートの名前は、1つのファイル名（英数字・`_`・`-`）だけを
  受け付ける（配置場所の外は読み込まない。Job YAML・CLI も同じ）

### 10.6 PACS の画面

- **送信失敗の理由**：接続できない、接続を断られた、送信中の切断、応答なし、
  画像の拒否（状態の値つき）、ファイルを読めない場合を、日本語で知らせる。
  表の最後の列は幅を制限し、理由を1行で切る。全文と元の文言は、行を選んだときの
  詳細の「失敗の理由」に出す。元の文言は等幅で出す。日本語の理由はそのまま使い、
  未知の理由は「送信に失敗しました」と出す。
- キューを読めないときはエラーだけを出し、「送信ジョブはまだありません。」は出さない。
- **画面の形**（画面の型 F「区画＋下に一覧」。tsunagi-dicom の `docs/design-system` の
  screen-types.md）：見出しの行（題「PACS」）の下に、上段の区画「接続先」と、下段の
  区画「送信ジョブ」を並べる（区画の見出しは 14px の太字）。下段は、見出しの右の
  [失敗 n 件を再送信]（n は条件で絞らない失敗の件数。0 件のときは押せない
  [失敗をすべて再送信]）→ 状態の要約 → 検索の帯 → 件数の行 → 一覧 → 境目 → 選んだ行の
  詳細の順に置く。[失敗 n 件を再送信] を押すと確認の窓（標準の `dialog`）が出て、窓の
  [再送信する] を押すまで何も送らない（[キャンセル] で閉じる）。
  ジョブの表の上に件数の行（「n 件」と「新しい順・2 秒ごとに自動更新」）を置く。ジョブが
  ないときは、表の見出しの行を残し、その下に空の状態「送信ジョブはまだありません。／撮影して
  送信すると、ここに出ます。」を出す。条件か状態で絞って 0 件のときは、「条件に合う送信ジョブは
  ありません。／条件を変えて、もう一度検索してください。」を出す。状態（送信ジョブ・保管の確認）と接続確認の結果は、枠・印・文字の
  札で出す（待ち ○・途中 ◔・完了 ✓・失敗 ✕。色は枠と印だけ）。行の中のボタンは高さ 24px の副にする

- **状態の要約と検索の帯**：状態の要約は、「すべて」と状態（送信中・送信完了・送信失敗。
  送信待ちは画面から作った件には残らないので並べない）ごとの件数のボタン。押した状態に
  一覧を絞り（押している状態は地と太字で示し、`aria-pressed` を付ける）、もう一度押すと
  絞りを外す。件数は、検索の帯の条件で絞った件の中で数える。検索の帯は、期間（すべて・今日・
  1 週間。初期は「すべて」。受付日時の日付で絞る）・送信先（すべて・設定の送信先）・患者ID（含む。
  大文字小文字を区別しない）と、[検索]・[条件をクリア]（画面を開き直す）。条件・状態・選んだ行は、
  2 秒ごとの再取得と再送信の応答でも保つ。知らない値は初期の値に戻す。
- **接続先の一覧**（区画「接続先」）：送信先ごとの行と、ワークリストの取得先の行を 1 つの表に
  置く。列は 名称・種類（送信先は保管確認（Storage Commitment）を使うかを小さく添える）・
  AEタイトル・ホスト名:ポート番号・最後の接続確認・操作（[接続確認]）。区画の見出しの右に
  [すべて接続確認]（副）を置き、押すとすべての行を確かめて区画を差し替える。「最後の接続確認」の
  列には、画面を動かしている間に覚えた最後の結果（札の「成功」か「失敗」と時刻、失敗は理由の
  1 句〔応答がありません・接続を断られました・相手が失敗を返しました・AEタイトルが合いません〕。
  まだ試していなければ
  「—」）を出す。確かめている間は、その行の列を札「確認中」にし、ボタンを押せなくする。
  押した直後は、区画の上に知らせを出す（成功は「PACS_TEST（127.0.0.1:4242）に接続できました
  （12 ms）。」、失敗は何が起きたか・理由・次にすることの 3 つ）。英語の原文は画面に出さず、
  記録に残す。最後の結果は、上の帯の接続の状態（10.3）と同じものを使う
- **送信キューと送信の履歴**：1つの表にまとめる。検査ごとの行（ID・状態・
  送信先・受付番号（画像の Accession Number。空なら「—」）・送信できた画像数／画像数・
  時刻・出力フォルダ）。新しい件を
  上にする。状態は 8.2 の「送信待ち・送信中・送信完了・送信失敗」。失敗の行は理由と
  [もう一度送る]（送れていない画像だけ）。送信完了の行にも [もう一度送る]（新しい件として全部。
  12 の 8.2）。送信中・送信待ちの行には出さない。見出しの右に [失敗 n 件を再送信]。
  2 秒ごとに再取得する。再送信を押してから応答が返るまでは、再取得を止め、直前に出て
  いた再取得の応答でも表を差し替えない（ボタンを押せなくした状態を保つ）。この間は、
  押した行だけでなく、表の中と詳細のすべての [もう一度送る] と、窓の [再送信する] を押せなくする
  （同じ件を2つの要求が同時に再送信しないように）。応答が返ったら押せる形に戻す。再取得で
  表を差し替えても、狭い画面で横にスクロールしている位置は保つ。出力
  フォルダはコピーのボタンでコピーできる。検査日時・受付日時・完了日時の見出しには、
  画面を動かすマシンの時刻の UTC からの差（`UTC+09:00`）を添える
- **選んだ行の詳細**：行の [詳細] を押すと、その行を選び（地と左の線で示し、
  `aria-selected="true"` を付ける）、一覧の下の境目の線の下に詳細を出す。選ぶまでは詳細の
  区画を出さない。詳細は、状態の知らせ（送信完了は成功、送信失敗は理由、そのほかは件数）、
  ジョブ・患者・受付番号・送信先・受付・完了の時刻、送信できた画像、失敗の理由（元の文言つき）、
  元のファイル（出力フォルダ。コピーのボタンつき）・試行回数・名乗る AEタイトルと、
  [もう一度送る]・[閉じる]。[閉じる] を押すと、選びを外して詳細を閉じる。2 秒ごとの再取得で
  表を差し替えても、選んだ行と詳細は保ち、フォーカスも同じボタンに戻す。条件や状態の絞りで
  選んだ件が一覧から外れたときは、詳細を閉じる
- 再送信の結果は表の上に出し、2 秒ごとの再取得では消さない。送信完了の件の再送信は
  「ジョブ 24 として再送信しました（送信完了）」のように新しい件の番号を出し、送信
  失敗の件の再送信は「1 件を再送信しました（送信完了 1 件）」と出す。失敗が残るときは
  「1 件を再送信しましたが、まだ送信できていません（送信完了 0 件・送信失敗 1 件）」と
  エラーの知らせ（`notice-error`・`role="alert"`）を出す。新しい件としての再送信も、
  新しい件が送信失敗ならエラーにする。再送信できないとき
  （送信中の件など）と、サーバーに届かなかったときも、表を残して同じ場所に理由を出す
- **保管確認の結果**：「確認待ち・確認済・確認の失敗・確認の時間切れ」。送信
  キューの表に「保管の確認」の列を1つ追加して表示する（保管確認を使わない送信先の
  件は「—」）。失敗の行には、失敗した画像数か理由（Association を確立できない、
  など）を小さく表示する。再要求のボタンは無い（CLI の `commit --job ID`。8.3.3）
- 次のものは無い：送信待ちの件の [送信]・[取り消す]（画面から作成した件はすぐ送信
  するので送信待ちに残らない）、履歴の日付の絞り込み、行の患者の氏名（送信キューは
  氏名を持たない）、画面を起動し直したあとも残る接続確認の記録（最後の結果は
  画面を動かしている間だけ覚える）

### 10.8 画面の文言

通信で要求が届かなかったときは「サーバーに届きませんでした。接続を確かめてから、

| PACS のボタン | 接続確認・もう一度送る・失敗をすべて再送信 |

### 10.9 待ち受けと認証

**初期設定はループバック（`127.0.0.1`）だけで待ち受け、認証は付けない。** 例外は
1つ：ループバック以外のアドレス（`0.0.0.0` など）で待ち受けるときは、認証を
必須にする（ADR-0011 の決定 5）。

- ループバック以外で待ち受ける設定で、パスワードの設定が無ければ起動しない
  （エラーで停止し、理由を表示する）
- 認証は HTTP Basic（利用者 1 人）。パスワードは環境変数 `DTG_WEB_PASSWORD_FILE`
  が指すファイルから読み込む。初期値を置かない。設定ファイルに平文で書かせない
- 書き込みのリクエスト（POST）は、`Origin` ヘッダー（無ければ `Referer`）の
  ホストとポートが、リクエストの `Host` と同じときだけ受け付ける（ほかのサイトからの
  リクエストを拒否する。どちらも無いリクエストも拒否する）。あわせて、起動のたびに
  作成する CSRF トークンをページに埋め込み、POST のヘッダー `X-CSRF-Token` か
  フォームの項目 `csrf_token` で返させ、一致しなければ拒否する（403）
- ループバック（`127.0.0.1`・`::1`・`localhost`）で待ち受けるときは、`Host`
  ヘッダーがループバックの名前のときだけ受け付ける（DNS rebinding で、ほかのサイトの
  ページからローカルの画面を読み取らせないため）
- `Host`・`Origin`・`Referer` ヘッダーが URL として解析できない（例 `Host: [`）
  ときは、例外にせずに拒否する（`Host` は 400、`Origin`・`Referer` は 403）
- ユーザー名は `dtg`。パスワードのファイルは起動時に1回読み込み、前後の空白と
  改行を除去する。ファイルが無い・読めない・空なら起動しない。
  `DTG_WEB_PASSWORD_FILE` があれば、ループバックで待ち受けるときも認証を付ける
- 応答には `Content-Security-Policy`（同一オリジンのリソースだけを読み込む。
  インラインのスクリプトを使わない）・`X-Content-Type-Options: nosniff`・
  `Referrer-Policy: same-origin`・`X-Frame-Options: DENY` を付ける
- HTTPS には対応しない。ネットワークに公開するときは、前段のリバースプロキシで TLS
  を終端することを README に書く
- テスト用のツールなので、利用者の管理・二要素認証・監査ログは持たない

## 11. CLI

[04_cli.md](04_cli.md) の形式に合わせ、`python -m app.cli` のサブコマンドとして
持つ。引数の正本は各サブコマンドの `--help` で、この章はその意味と規則を書く。

どのサブコマンドも次を持つ。

| オプション | 説明 | デフォルト |
|-----------|------|-----------|

### 11.1 サブコマンド

| コマンド | 説明 |
|---------|------|
| `echo` | 送信先・ワークリストの取得先に C-ECHO |
| `worklist query` | ワークリストを検索して一覧を出力する |
| `worklist show <キー>` | 最後に取得した予約の1件の値を出力する |
| `exam` | 予約（または緊急の患者）で撮影する |
| `send` | 出力フォルダの画像を送信する |
| `queue list` | 送信キューと履歴を出力する |
| `queue retry` | 失敗した送信を再送信する。`--job` は送信完了の件も新しい件として再送信する |
| `commit` | 送信した検査の保管確認を要求する |

### 11.4 exam

```bash
# 予約で撮影する（最後に取得した結果から）
python -m app.cli exam --from-worklist 3f9a1c0b2e -s 2 -i 1,20
```

| オプション | 説明 | デフォルト |
|-----------|------|-----------|
| `--from-worklist KEY` | 予約のキー | — |
| `--refresh` | 撮影の前にその予約を再取得する | false |
| `--append` | 撮影済みの予約で追加撮影する（12 の 6.3。`retake_mode: append` のときだけ。撮影済みでない予約・`new_order` では終了コード 4）。`--emergency` と使うときは `--study-uid` が必須（12 の 6.3。`retake_mode` によらない） | false |
| `--study-uid UID` | 緊急の患者の追加撮影で、前の緊急の撮影の Study Instance UID（`--emergency --append` のときだけ。ほかで指定すると終了コード 2） | — |
| `--emergency` | 予約なし。`--patient-*` が必須 | false |
| `-m, --modality NAME` | テンプレート | 設定の初期値 |
| `--profile NAME` | 装置プロファイル（spec/13。画面の「装置」と同じ） | 設定の初期値（`default_profile`） |
| `--hospital NAME` | 病院テンプレート | 設定の初期値 |
| `-s, --series N` | シリーズ数（手で入れる。`-i` だけなら `-i` の項目の数） | — |
| `-i, --images LIST` | 各シリーズの画像数（手で入れる） | `-s` だけなら、シリーズごとに 1 枚 |
| `--routine NAME` | 撮影のルーチン（`templates/routine/`。10.5・ADR-0025） | `-s`・`-i` を省くと、予約に当てたルーチン |
| `--routine-images LIST` | ルーチンの各シリーズの画像数（数はルーチンのシリーズの数と同じ） | ルーチンの標準の数 |
| `--pixel-mode MODE` | ピクセル | 設定の初期値 |
| `--abnormal-level L` | 異常のデータ | none |
| `--charset C` | `auto`・`utf8`・`jis`・`jis_kana`（Orthanc 1.13.0 へ送る画像は `utf8` か `jis`。[spec/12](12_modality_emulator.md) の 14.4） | 設定の初期値 |
| `-o, --output DIR` | 出力フォルダ | 設定の初期値 |
| `--send` | 作成した後に標準の送信先へ送信する | false |
| `--to NAME` | `--send` の送信先 | 標準の送信先 |
| `--study-description TEXT` | 検査名（`--emergency` のときだけ） | 空 |
| `--patient-id`・`--patient-name` | 緊急の患者の ID・氏名（PN。`--emergency` のとき必須。英字の成分グループは空にできない。10.5） | — |
| `--birth-date`・`--sex` | 緊急の患者の生年月日（YYYYMMDD）・性別（M/F/O）。省略すると空 | 空 |
| `--json` | 結果を JSON で出力する | false |
| `--mpps`・`--no-mpps` | この撮影だけ MPPS を送信する・送信しない（8.4.1） | 設定（`worklist.use_mpps`） |

`--from-worklist` と `--emergency` はどちらか1つを必須にする。

- `-s`・`-i`・`--routine` を省くと、画面と同じ決まり（10.5）で当てたルーチンの並びと
  枚数で撮る。`--routine`・`--routine-images` と `-s`・`-i` を一緒に指定したら、撮影
  せずに終了コード 4。`--routine-images` の数がシリーズの数と違っても終了コード 4
- 結果の行と `--json`（`routine`）に、使ったルーチンの名前を出す。手で入れた撮影は
  `null`

- 出力は `<出力フォルダ>/<受付番号か emergency>_<撮影の日時 YYYYMMDDHHMMSS>/`
  に書き出す（受付番号は 6.5 の規則でファイル名に変換する。同じ秒に同じ名前が
  あれば `_2`・`_3` を追加する）。同じ予約で2回撮影すると、別のフォルダに同じ
  Study の新しいシリーズができる
- `-i` の数は `-s` と同じ数にする（`quick` と同じ）
- 撮影の画面で停止する・確認を求める場面は、CLI では次のとおりにする
  - テンプレートと予約のモダリティが異なる・値が長さの制約を超える・表現できない
    文字・読めない値：停止する（終了コード 4）
  - 予約の予定の AEタイトルが自分と異なる・Study Instance UID を生成した・生年月日
    や性別が空：通知（`[NOTICE]`。`--json` では `notices`）を出して撮影する
- MPPS を送信できなかったときも撮影は成功とし（終了コード 0）、標準エラー出力に
  `[WARN] MPPS ...` を出す。`--json` では `mpps`（`state`・`sent`・`error`）に
  入れる。MPPS を使わない撮影では `mpps` は `null`

### 11.5 send・queue

```bash
python -m app.cli send output/modality/A0001_20261018090000/ --to PACS_TEST
python -m app.cli queue list --status failed
python -m app.cli queue retry --all
python -m app.cli queue retry --job 3
python -m app.cli queue retry --stale
```

- `send FOLDER`：フォルダの `*.dcm` を送信キューに1件（1つの検査）として入れ、
  すぐに送信する。`--to` が無ければ標準の送信先
- `queue list`：`--status` は `pending`（送信待ち）・`sending`（送信中）・
  `sent`（送信完了）・`failed`（送信失敗）。`--json` で JSON
- `queue list`：停止した送信中（8.2）の件には `[STALE]` を付ける。`--json` では
  `stale` が `true`
- `queue retry`：`--all`（失敗のすべて）・`--job ID`・`--stale`（停止した送信中の
  すべて。失敗に戻してから送信する）のどれか1つを必須にする。失敗した件は、失敗した
  ファイルだけを再送信する。`--job` に送信完了の件を指定したときは、同じフォルダの
  画像をすべて、同じ送信先へ新しい件として送信する（何回でもできる。12 の 8.2）
- `queue list`：保管確認の状態を `COMMIT` の列に出力する（`waiting`・`confirmed`・
  `failed`・`timed_out`。使わない件は `-`）。`--json` では `commitment`
  （使わない件は空文字列）と `commitment_error`

### 11.6 終了コード

通信の失敗（Association を確立できない・拒否された・相手が Failure を返した・
タイムアウト）は 5 にする。[04_cli.md](04_cli.md) の表も同じ。

| コード | 意味 | この章で起きる例 |
|-------|------|------------------|
| 0 | 成功 | — |
| 1 | 一般エラー | 作成の失敗 |
| 2 | 設定エラー | `modality:` の節のエラー（`ModalityConfigError`） |
| 3 | I/O エラー | 出力フォルダに書き込めない |
| 4 | バリデーションエラー | 予約の値を転記できない（`WorklistMappingError`）・表現できない文字 |
| 5 | 通信エラー | `AssociationError`・`WorklistQueryError`・`StoreError`・`StorageCommitmentError`（`commit` が確認済にならない）・`MPPSError`（`mpps retry` で送信できない分が残る） |

- 結果は標準出力、エラーは標準エラー出力
- `--json` のときは標準出力に JSON だけを出力する

### 11.7 相手から来る値を端末に出力するとき

**ワークリストの値（氏名・記述など、相手から来る値）は、端末に出力する前に制御文字を
可視化する。** 例外は無い。ESC・CSI・OSC などをそのまま出力すると、端末の表示や
タイトルを書き換えられるため。

- 置き換える文字：C0（U+0000〜U+001F）・DEL（U+007F）・C1（U+0080〜U+009F）・
  Unicode の双方向制御文字（U+061C・U+200E・U+200F・U+202A〜U+202E・U+2066〜
  U+2069）・行と段落の区切り（U+2028・U+2029）
- 通常の出力：`\x1b`・`‮` のような可視の形にする（`app/cli/terminal.py` の
  `sanitize_for_terminal`）。標準エラー出力のエラーメッセージも同じ
- `--json`：同じ文字を JSON の `\uXXXX` に変換する（`json_for_terminal`）。
  デコードすると元の値に戻る（値そのものは変えない）
- ログに相手から来る値を出力するときは `%r` で出力する（制御文字がエスケープ
  される）。Patient ID も相手から来る値として扱う
- 端末（標準エラー出力）に出すログは、整形した後の文字列を行ごとに
  `sanitize_for_terminal` で処理する（改行は残す。例外の Traceback も同じ）。
  ファイルのログはそのまま

### 11.8 commit

```bash
python -m app.cli commit --job 3
python -m app.cli commit --job 3 --wait 60 --json
```

| オプション | 説明 | デフォルト |
|-----------|------|-----------|
| `--job ID` | 送信キューの ID（必須。状態が送信完了の件だけ） | — |
| `--wait SECONDS` | 結果を待つ秒数（1 以上） | 送信先の `commitment_timeout_seconds` |

- 送信先が保管確認を使わない（`storage_commitment: false`）なら、送信せずに
  終了コード 2 で停止する
- 待ち受け（`modality.listen`）を起動してから N-ACTION を送信し、結果か `--wait`
  の秒数まで待つ。待ち受けを起動できない（ポートが使用中）ときは、送信せずに
  終了コード 2 で停止し、画面が動いていないかを確認するよう表示する
- 結果が確認済なら終了コード 0。確認の失敗、または `--wait` の間に来ない（状態は
  確認待ちのまま。時間切れはキューが判定する）なら終了コード 5
- 出力は件の ID・状態・確認できた画像数／要求した画像数。`--json` では `job_id`・
  `transaction_uid`・`status`・`num_requested`・`num_confirmed`・`num_failed`・
  `error`
