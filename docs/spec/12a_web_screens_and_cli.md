## 10. Web 画面

### 画面の方向

**画面はすっきりさせる。余白を取り、部品を少なくし、一画面でやることを1つに
する。** クラウド型の電子カルテのような、余白の多い静かな画面を目安にする。
例外は無い。

- DTG は診療のためではなく、システムの試験でモダリティの代わりに使う。技師の
  操作の全部を写す必要は無く、試験に要る「取得→選ぶ→撮る→送る→確かめる」が
  迷わず流せればよい
- **機能は足すより削る。** 画面に何かを足したくなったら、まず試験に要るかを
  問う。要らなければ足さない。CLI か設定のファイルでできることは、画面に
  出さなくてよい
- 一画面の主のボタンは1つにする（例：ワークリストは「選んで撮影へ」、撮影は
  「撮影して送る」）。ほかの操作は枠線のボタンか背景の無いボタンにして控えめに
  する
- 詳しい値（予約の値の全部・UID など）は最初から並べず、開いて見せる
  （パネル・折りたたみ）

### 10.1 技術

**画面は、サーバー側で描く Web 画面（FastAPI・Jinja2・HTMX・Tailwind CSS の
standalone の実行ファイル）にする。** 選んだ理由は ADR-0011 にある。

- Node は要らない。Tailwind CSS v4 は standalone の実行ファイル（GitHub の
  releases に OS ごとの実行ファイルと `sha256sums.txt` がある）で CSS を作れる。
  版を固定し、sha256 を確かめてから使う
- 作った CSS（`app/web/static/app.css`）は commit する。利用者は Tailwind の
  実行ファイル無しで動かせる
- htmx は1つの JavaScript のファイルを `app/web/static/` に置く（版を固定し、
  入手元と sha256 を [development.md](../development.md) の 8 章に書く）。外の CDN
  からは読まない。ネットワークにつながない環境でも動かすため
- アイコンは Lucide（ISC License）の SVG を、使う分だけ `app/web/static/icons/`
  に置く。ライセンスの文を同じ場所に置く
- Python のパッケージは `fastapi`・`uvicorn`・`jinja2`・`python-multipart`
  （フォーム）、試験用に `httpx`（FastAPI の TestClient が使う）
- 画面の更新（送信キューの状態など）は HTMX の定期の取得
  （`hx-trigger="every 2s"`）で行う。SSE・WebSocket は使わない
- 色と文字の値は、入力の CSS（`app/web/styles/input.css`）に書く。値が 10.2 の表と
  ずれたら気づけるよう、試験で比べる（`tests/web/test_theme_tokens.py`）

### 10.2 見た目の基準

**画面（ワークリスト・撮影・PACS・設定）は、ライトテーマを既定にし、
ダークテーマにも切り替えられる。** 例外は1つ：画像のサムネイルを並べる所だけ、
まわりをダークテーマにする。

- これらは文字を読む画面である。日本の医療機関で広く使われている画面でも、画像を
  見る画面は暗い背景、一覧や事務の画面は明るい背景が多い
- テーマの切り替えはヘッダーのボタンで行い、ブラウザの `localStorage` に
  覚える。覚えが無ければライトテーマ
- どちらのテーマでも、基準の文字 14px（0.875rem）・行間 1.5。表の行・入力の欄も
  14px を下回らない（補いの文字だけ 12px）
- 部品の間の余白は広めに取り、詰めない：パネルの間は 16〜24px、パネルの中の欄の
  間は 12px 以上、ページの左右は 16px 以上。1画面に詰め込まず、詳細はパネルを
  開いて見せる
- 文字と背景のコントラスト比は WCAG 2.2 の AA（4.5:1）以上にする

| 名前 | ライトテーマ（既定） | ダークテーマ | 用途 |
|------|----------------------|--------------|------|
| `--color-background` | `#ffffff` | `#121417` | 背景 |
| `--color-surface` | `#f6f8fa` | `#1a1d21` | ヘッダー・パネルの背景 |
| `--color-foreground` | `#1f2328` | `#e6edf3` | 文字 |
| `--color-label` | `#59636e` | `#8a949e` | ラベル |
| `--color-value` | `#1f2328`（太字） | `#ffffff`（太字） | 値 |
| `--color-border` | `#d1d9e0` | `#2a2f36` | 枠線 |
| `--color-muted` | `#eff2f5` | `#23272d` | 行の hover・弱い背景 |
| `--color-primary` | `#0969da` | `#1f6feb` | 主のボタン・フォーカスの輪 |
| `--color-primary-foreground` | `#ffffff` | `#ffffff` | 主のボタンの文字 |
| `--color-danger` | `#d1242f` | `#ff7b72` | 失敗・止める通知の文字 |
| `--color-success` | `#1a7f37` | `#3fb950` | 撮影完了・送信完了の枠と印 |
| `--color-warning` | `#9a6700` | `#d29922` | 注意（予約なし・生年月日が空など）の枠と印 |
| `--font-sans` | `system-ui, "Noto Sans JP", sans-serif` | 同じ | 本文 |
| `--font-mono` | `ui-monospace, "Noto Sans Mono", monospace` | 同じ | UID |

- コントラスト比（WCAG 2.x の相対輝度の式で計算）：ライトテーマの文字 `#1f2328`
  は `#ffffff` に 15.8:1・`#f6f8fa` に 14.8:1、ラベル `#59636e` は 6.1:1・5.7:1。
  ダークテーマの文字 `#e6edf3` は `#121417` に 15.6:1、ラベル `#8a949e` は
  `#1a1d21` に 5.5:1。いずれも AA を満たす
- ライトテーマの `--color-muted`（`#eff2f5`）の上で、文字 `#1f2328` は 14.1:1、
  ラベル `#59636e` は 5.4:1、主の色 `#0969da` は 4.6:1 で、どれも AA を満たす。
  ダークテーマの `#23272d` の上では、文字 `#e6edf3` が 12.7:1、ラベル `#8a949e`
  が 4.9:1
- `--color-danger` は、ライトテーマの `#d1242f` が `#ffffff` に 5.2:1・
  `#f6f8fa` に 4.9:1・`#eff2f5` に 4.7:1、ダークテーマの `#ff7b72` が `#121417`
  に 7.3:1・`#1a1d21` に 6.7:1・`#23272d` に 6.0:1 で、どれも AA を満たす
- `--color-success`・`--color-warning` は枠と印の色で、文字は
  `--color-foreground` のまま。ライトテーマの `#1a7f37` は `#ffffff` に 5.1:1・
  `#f6f8fa` に 4.8:1、`#9a6700` は 4.9:1・4.6:1。ダークテーマの `#3fb950`・
  `#d29922` は `#121417` に 7.3:1、`#1a1d21` に 6.7:1 で、どれも AA を満たす
- **結果の言い方**は、現場の PACS・モダリティの用語にそろえる：撮影の結果は緑の
  枠で「撮影完了：14 画像」、送信は「送信完了：ORTHANC へ 14/14 画像（ジョブ 11）」
  （失敗は赤の枠で「送信失敗：…」）。予約なし・生年月日が空などの注意は黄の枠で、
  結果とは分けて並べる。枚は「画像」、送信キューの1件は「ジョブ」、ネットワークの
  相手は「ホスト」と書く
- **ライトテーマの主の色は `#0969da`。** 白の背景とのコントラスト比は 5.19:1、
  `#f6f8fa` の背景とは 4.88:1、主のボタンの白の文字とは 5.19:1 で、どれも AA
  （4.5:1）を満たす
- **ダークテーマの主の色は `#1f6feb`。** 主のボタンの背景で、白の文字との
  コントラスト比は 4.63:1（AA を満たす）。`--color-primary-foreground` は両方の
  テーマで `#ffffff`。注意：`#1f6feb` はダークテーマの背景（`#121417` に
  3.98:1、`#1a1d21` に 3.65:1）の上では、文字には使えない（AA の 4.5:1 に
  届かない）。フォーカスの輪など文字でない図形の色は 3:1 以上が目安で、満たす
- 部品の形：
  - ボタン：高さ 32px（`h-8 px-3`）、角 `rounded-md`、文字 `text-sm`
    `font-medium`、アイコン 16px。種類は主（`bg-primary`）・枠線
    （`border border-border`）・背景の無いもの（`hover:bg-muted`）の3つ
  - 表：見出しの行は `h-9`・ラベルの色・`font-normal`、セルは `px-2 py-1.5`、
    行の線 `border-b border-border`、hover で `bg-muted/50`
- フォントの名前に商用のフォントを書かない

### 10.3 共通の部品

- **ヘッダー**（どのページにも1つ）：左にツールの名前（`dicom-test-generator`、
  太字・値の色）、真ん中にページの切り替え（ワークリスト・撮影・PACS・設定）、
  右にテーマの切り替え。「Not for Diagnostic Use / 非医療機器」の表示は
  出さない。機能ごとの注意書きは足さない
- **自分の帯**（ヘッダーの下）：自分の AE タイトル・ワークリストの相手・既定の
  送り先・文字コード（ワークリスト → 画像）を1行で出す
- **通知**：操作の結果（成功・失敗）を、その操作のボタンの下に出す。失敗は
  次の操作まで消えずに残す。右上に浮かべる通知は作らない
- 患者の値の出し方：漢字の氏名は 14px・太字・値の色、かなの氏名は 12px・
  ラベルの色、生年月日は `1975/05/10（51歳・男）` の形。UID は 0.75rem・等幅・
  ラベルの色で、コピーのボタンを付ける

### 10.4 ワークリストの画面

```text
┌ dicom-test-generator  [ワークリスト] 撮影  PACS  設定                                    ┐
│ 自分: DTG_CT01 │ ワークリスト: RIS_TEST │ 送り先: PACS_TEST │ 文字: ISO_IR 192 → ISO_IR 192 │
├──────────────────────────────────────────────────────────────────────┤
│ 予定の日 [今日 ▼]  モダリティ [CT ▼]  AE [自分 ▼]                       │
│ 患者 ID [      ]  氏名 [      ]  受付番号 [      ]   [ワークリストを取得]  │
├──────────────────────────────────────────────────────────────────────┤
│ 時刻  患者 ID   氏名            生年月日・性別        受付番号  検査の記述 │
│ 09:00 P000001  山田 太郎        1980/01/15（45歳・男） A0001    胸部 CT   │
│              やまだ たろう                                            │
│ 09:30 P000002  …                                                      │
├──────────────────────────────────────────────────────────────────────┤
│ 12 件（14:05:31 に取得）                     [選んで撮影へ] [取得し直す] │
└──────────────────────────────────────────────────────────────────────┘
```

- 行を選ぶと、一覧の下に詳細のパネル（予約の値の全部・Study Instance UID・
  Scheduled Procedure Step ID・予定の AE タイトル・文字コード）
- 予定の日は「今日・明日・日付を指定・絞らない」から選ぶ。範囲は CLI の `--date`
  で取得する。モダリティの欄は空にすると絞らない。AE は「自分・絞らない」から選ぶ
- 条件を戻すボタンと、Requested Procedure ID の欄は無い。ページを開き直せば既定の
  条件に戻る
- ボタンの言葉は「ワークリストを取得」「取得し直す」にする（モダリティの画面の
  普通の言い方。CLI の `worklist query`・`--refresh` の名前は変えない）
- 「取得し直す」は、選んだ予約を受付番号と Requested Procedure ID で取得し直し、
  最新の値にする
- 予定の AE タイトルが自分と違う予約は、行に「別の装置」の印を付ける
- 0 件のとき：「予約はありません。条件を広げるか、緊急の患者で撮ってください」と、
  [緊急の患者で撮る] のボタン

### 10.5 撮影の画面

```text
┌ 予約の値（読むだけ） ───────────────────────────────────────────┐
│ 患者 ID P000001   氏名 山田^太郎=やまだ^たろう   1980/01/15・男  │
│ 受付番号 A0001   検査の記述 胸部 CT   Study UID 2.25.1234… [⧉]    │
│ ワークリストの文字コード ISO_IR 192                                │
├ 撮影の設定 ─────────────────────────────────────────────────────┤
│ テンプレート [ct_generic ▼]  装置 [なし ▼]  文字コード（画像）[auto ▼] │
│ シリーズ数 [2]  画像数 [1, 20]  異常のデータ [なし ▼]              │
│ 1回の撮影は合計 2000 画像まで。                                   │
│ MPPS：使わない                                                    │
├─────────────────────────────────────────────────────────────────┤
│ [撮影] [撮影して送る]                                              │
└─────────────────────────────────────────────────────────────────┘
```

- 予約の値は入力の欄にしない（読むだけ）。直したいときは RIS の側で直して
  「取得し直す」
- テンプレートのモダリティと予約のモダリティが違えば、[撮影] を押せなくし、
  「予約は MR、テンプレートは CT です」と出す
- 「装置」は装置のプロファイル（[13_device_profiles.md](13_device_profiles.md)）。
  選べばテンプレートの上に重ねる。プロファイルのモダリティが予約と違うときも
  同じく止める
- 緊急の患者：予約なしで開いたときは、患者の値（ID・氏名の英字・漢字・かな・
  生年月日・性別）を入力の欄にする。受付番号は空で固定し、「予約なし（受付番号は
  空）」と出す
- **必須の欄**：緊急の患者の「患者 ID」と「氏名（英字）」、撮影の設定の
  「シリーズ数」と「画像数」。欄の名前の横に「必須」の印を付け、空なら送れなく
  する（画面の `required`）。サーバー側でも確かめ、空なら撮らずに止める
  （`ModalityService` が `ValidationError`。CLI の `exam --emergency` も同じで、
  `--patient-name` の英字の成分グループが空なら終了コード 4）。ほかの欄（漢字・
  かな・生年月日・性別・検査の記述）は空でよい
- **氏名の姓と名の区切り**：利用者は `^` を打たないので、英字・漢字・かなの3つの
  欄で、空白を `^` に置き換える
  - 置き換え方：前後の空白を落とし、`^` の前後の空白を落とし、続いた空白
    （半角・全角とも）を1つの `^` にする。例「Yamada Taro」→「Yamada^Taro」、
    「山田　太郎」→「山田^太郎」。既に `^` で区切った値はそのまま
  - 画面では欄からカーソルが離れたとき（blur）に置き換えて見せる（補助）。
    サーバー側（`ModalityService.emergency_person_name`）でも同じ置き換えを
    するので、スクリプトが無効でも同じ値になる
  - `=`（成分グループの区切り）と制御文字は、どの欄でも断る（`ValidationError`）
- **`\` は断る**：`\` は DICOM の値の区切り（PS3.5 6.2）で、LO・PN・SH に
  入れると同じ属性の値が複数になり、VM 1 の属性（Patient ID・Patient's Name・
  Study Description）に合わない。緊急の患者の「患者 ID」「氏名」と「検査の記述」に
  `\` があれば、サーバー側（`ModalityService.exam`）で `ValidationError` にして
  撮らない（画面・CLI とも。CLI は終了コード 4）
  - 一覧・撮影の画面の表示では、`^` を空白にして出す
- 主のボタンは [撮影して送る]（既定の送り先へ）。[撮影] は枠線のボタンにし、
  撮った後の結果に [送る] を出す
- **シリーズ数を変えたときの画像数**：シリーズ数を変えたら、画像数の欄を
  シリーズごとに同じ数で自動入力する（先頭の数を並べる。例：シリーズ数 3・
  画像数 `2` → `2,2,2`）。画像数を手で直した後は上書きしない。CLI の `exam -i` を
  省いたときも、シリーズごとに 1 枚で埋める（`-s 3` なら `1,1,1`）
- **二度押しの対策**：[撮影]・[撮影して送る]・[送る] を押したら、応答が返るまで
  ボタンを押せなくし、途中の表示（スピナーと「撮影しています」「撮影して
  送っています」「送信しています」）を出す。前の結果は新しい要求の前に消す。
  サーバーに届かなかったときは、結果の場所に通知する。サーバー側でも、撮影の
  画面が出すトークン（`exam_token`）を受け付けた撮影ごとに覚え、同じトークンの
  撮影は2回受けない（撮っている間も、撮り終えた後も）。失敗した撮影のトークンは
  戻す。撮り終えた応答が新しいトークンを渡すので、続けて別の撮影をするときは
  画面を開き直さなくてよい。トークンの無い要求（スクリプトなど）は受ける
- 画面には「病院」「ピクセル」の欄と、進捗のバー・取り消しは無い。病院と
  ピクセルは設定の既定を使い、CLI の `--hospital`・`--pixel-mode` で選べる。作る
  画像は試験の分だけで、待たずに終わるため、進捗は出さない
- **MPPS**：撮影の画面には状態を出すだけにする（選ぶ欄と再送のボタンは無い。
  使うかは設定で決め、再送は CLI の `mpps retry`）。撮影の設定の下に
  「MPPS：使う（相手の AE タイトル）」か「MPPS：使わない」を1行で出す。撮った
  後の結果に、その撮影の MPPS の状態を1行で出す：「MPPS：COMPLETED を
  送りました」「MPPS：DISCONTINUED を送りました」「MPPS：送れませんでした
  （理由）。`python -m app.cli mpps retry` で再送します」
- 「文字コード」は撮影の設定の欄に置き、設定の既定を初めの値にする
- **1回の撮影の量の上限**（1つの要求でディスクを埋めない）：
  - 1回の撮影の合計の画像数は、設定 `modality.max_images_per_exam`（既定 2000）
    までにする。`ModalityService.exam` が確かめ、超えたら撮らずに
    `ValidationError`（CLI は終了コード 4）。画面にも上限を出す
  - 画面では、あわせてシリーズ 99・1シリーズ 1000 画像までにする（欄の確かめ）
  - 同時に走る撮影は、1つの `ModalityService`（画面のプロセス）の中で1つに
    限る。走っている間に来た撮影は待たせずに断る（`ModalityError`。「ほかの撮影が
    走っています」）。別々の CLI のプロセスどうしは数えない
  - 空き容量は確かめない（合計の画像数の上限で抑える）
- 画面から来るテンプレートの名前は、1つのファイルの名前（英数字・`_`・`-`）
  だけを受ける（置き場の外を読まない。Job YAML・CLI も同じ）

### 10.6 PACS の画面

- **送り先の一覧**：名前・AE タイトル・ホスト・ポート・保管確認の有無。各行に
  [C-ECHO] と、押した結果（つながった（○ ms）・つながらない（理由））
- **送信キューと送った履歴**：1つの表にまとめる。検査ごとの行（ID・状態・
  送り先・受付番号・送れた画像数／画像数・時刻・出力のフォルダ）。新しい件を
  上にする。状態は 8.2 の「待機中・送信中・送信完了・送信失敗」。失敗の行は理由と
  [再送]。表の上に [失敗をすべて再送]。2 秒ごとに取得し直す。出力のフォルダは
  コピーのボタンで写せる
- **保管確認の結果**：「確認待ち・確認済・確認の失敗・確認の時間切れ」。送信
  キューの表に「保管の確認」の列を1つ足して出す（保管確認を使わない送り先の件は
  「—」）。失敗の行には、失敗した画像数か理由（Association を張れない、など）を
  小さく出す。求め直すボタンは無い（CLI の `commit --job ID`。8.3.3）
- 次のものは無い：待機中の件の [送る]・[取り消す]（画面から作る件はすぐ送るので
  待機中に残らない）、履歴の日付の絞り込み、行の患者の氏名（送信キューは氏名を
  持たない）、送り先ごとの最後の C-ECHO の時刻（押した結果だけをその場に出す）

### 10.9 待ち受けと認証

**既定はループバック（`127.0.0.1`）だけで待ち受け、認証は付けない。** 例外は
1つ：ループバック以外のアドレス（`0.0.0.0` など）で待ち受けるときは、認証を
必須にする（ADR-0011 の決定 5）。

- ループバック以外で待ち受ける設定で、パスワードの設定が無ければ起動しない
  （エラーで止まり、理由を出す）
- 認証は HTTP Basic（利用者 1 人）。パスワードは環境変数 `DTG_WEB_PASSWORD_FILE`
  が指すファイルから読む。既定値を置かない。設定ファイルに平文で書かせない
- 書き込みのリクエスト（POST）は、`Origin` ヘッダー（無ければ `Referer`）の
  ホストとポートが、リクエストの `Host` と同じときだけ受ける（ほかのサイトからの
  リクエストを断る。どちらも無いリクエストも断る）。あわせて、起動のたびに作る
  CSRF トークンをページに埋め、POST のヘッダー `X-CSRF-Token` かフォームの欄
  `csrf_token` で返させ、合わなければ断る（403）
- ループバック（`127.0.0.1`・`::1`・`localhost`）で待ち受けるときは、`Host`
  ヘッダーがループバックの名前のときだけ受ける（DNS rebinding で、ほかのサイトの
  ページからローカルの画面を読ませないため）
- `Host`・`Origin`・`Referer` ヘッダーが URL として読めない（例 `Host: [`）
  ときは、例外にせずに断る（`Host` は 400、`Origin`・`Referer` は 403）
- 利用者の名前は `dtg`。パスワードのファイルは起動のときに1回読み、前後の空白と
  改行を除く。ファイルが無い・読めない・空なら起動しない。
  `DTG_WEB_PASSWORD_FILE` があれば、ループバックで待ち受けるときも認証を付ける
- 応答には `Content-Security-Policy`（同じオリジンのものだけを読む。インラインの
  スクリプトを使わない）・`X-Content-Type-Options: nosniff`・
  `Referrer-Policy: same-origin`・`X-Frame-Options: DENY` を付ける
- HTTPS は持たない。ネットワークに公開するときは、前段のリバースプロキシで TLS を
  終端することを README に書く
- 試験用のツールなので、利用者の管理・二要素認証・監査の記録は持たない

### 11.4 exam

```bash
# 予約で撮る（最後に取得した結果から）
python -m app.cli exam --from-worklist 3f9a1c0b2e -s 2 -i 1,20

# 予約を取得し直してから撮って送る
```

|-----------|------|-----------|
| `--from-worklist KEY` | 予約の鍵 | — |
| `--refresh` | 撮る前にその予約を取得し直す | false |
| `--emergency` | 予約なし。`--patient-*` が必須 | false |
| `-m, --modality NAME` | テンプレート | 設定の既定 |

| `--hospital NAME` | 病院テンプレート | 設定の既定 |

| `-o, --output DIR` | 出力のフォルダ | 設定の既定 |
| `--send` | 作った後に既定の送り先へ送る | false |
| `--to NAME` | `--send` の送り先 | 既定の送り先 |
| `--study-description TEXT` | 検査の記述（`--emergency` のときだけ） | 空 |
| `--patient-id`・`--patient-name` | 緊急の患者の ID・氏名（PN。`--emergency` のとき必須。英字の成分グループは空にできない。10.5） | — |
| `--birth-date`・`--sex` | 緊急の患者の生年月日（YYYYMMDD）・性別（M/F/O）。省くと空 | 空 |

- 出力は `<出力のフォルダ>/<受付番号か emergency>_<撮影の日時 YYYYMMDDHHMMSS>/`
  に書く（受付番号は 6.5 の決まりで名前に直す。同じ秒に同じ名前があれば `_2`・
  `_3` を足す）。同じ予約で2回撮ると、別のフォルダに同じ Study の新しい
  シリーズができる
- `-i` の数は `-s` と同じ数にする（`quick` と同じ）
- 撮影の画面で止める・確かめを求める場面は、CLI では次のとおりにする
  - テンプレートと予約のモダリティが違う・値が長さの制約を超える・表せない字・
    読めない値：止める（終了コード 4）
  - 予約の予定の AE タイトルが自分と違う・Study Instance UID を作った・生年月日や
    性別が空：通知（`[NOTICE]`。`--json` では `notices`）を出して撮る
- MPPS を送れなかったときも撮影は成功とし（終了コード 0）、標準エラーに
  `[WARN] MPPS ...` を出す。`--json` では `mpps`（`state`・`sent`・`error`）に
  入れる。MPPS を使わない撮影では `mpps` は `null`

### 11.5 send・queue

```bash
python -m app.cli send output/modality/A0001_20261018090000/ --to PACS_TEST
python -m app.cli queue list --status failed
python -m app.cli queue retry --all
python -m app.cli queue retry --job 3
python -m app.cli queue retry --stale
```

- `send FOLDER`：フォルダの `*.dcm` を送信キューに1件（1つの検査）として入れ、
  すぐに送る。`--to` が無ければ既定の送り先
- `queue list`：`--status` は `pending`（待機中）・`sending`（送信中）・
  `sent`（送信完了）・`failed`（送信失敗）。`--json` で JSON
- `queue list`：止まった送信中（8.2）の件には `[STALE]` を付ける。`--json` では
  `stale` が `true`
- `queue retry`：`--all`（失敗の全部）・`--job ID`・`--stale`（止まった送信中の
  全部。失敗に戻してから送る）のどれか1つを必須にする。失敗のファイルだけを
  送り直す
- `queue list`：保管確認の状態を `COMMIT` の列に出す（`waiting`・`confirmed`・
  `failed`・`timed_out`。使わない件は `-`）。`--json` では `commitment`
  （使わない件は空の文字列）と `commitment_error`

### 11.6 終了コード

通信の失敗（Association を張れない・断られた・相手が Failure を返した・
時間切れ）は 5 にする。[04_cli.md](04_cli.md) の表も同じ。

| コード | 意味 | この章で起きる例 |
|-------|------|------------------|
| 0 | 成功 | — |
| 1 | 一般のエラー | 生成の失敗 |
| 2 | 設定のエラー | `modality:` の節の誤り（`ModalityConfigError`） |
| 3 | I/O のエラー | 出力のフォルダに書けない |
| 4 | バリデーションのエラー | 予約の値が写せない（`WorklistMappingError`）・表せない字 |
| 5 | 通信のエラー | `AssociationError`・`WorklistQueryError`・`StoreError`・`StorageCommitmentError`（`commit` が確認済にならない）・`MPPSError`（`mpps retry` で送れない分が残る） |

- 結果は標準出力、エラーは標準エラー
- `--json` のときは標準出力に JSON だけを出す

### 11.7 相手から来る値を端末に出すとき

**ワークリストの値（氏名・記述など、相手から来る値）は、端末に出す前に制御文字を
見える形に置き換える。** 例外は無い。ESC・CSI・OSC などをそのまま出すと、端末の
表示やタイトルを書き換えられるため。

- 置き換える字：C0（U+0000〜U+001F）・DEL（U+007F）・C1（U+0080〜U+009F）・
  Unicode の双方向の制御（U+061C・U+200E・U+200F・U+202A〜U+202E・U+2066〜
  U+2069）・行と段落の区切り（U+2028・U+2029）
- 通常の出力：`\x1b`・`‮` のような見える形にする（`app/cli/terminal.py` の
  `sanitize_for_terminal`）。標準エラーのエラーの文も同じ
- `--json`：同じ字を JSON の `\uXXXX` に直す（`json_for_terminal`）。読み戻すと
  元の値に戻る（値そのものは変えない）
- ログに相手から来る値を出すときは `%r` で出す（制御文字がエスケープされる）。
  Patient ID も相手から来る値として扱う
- 端末（標準エラー）に出すログは、整えた後の文を行ごとに `sanitize_for_terminal`
  に通す（改行は残す。例外の Traceback も同じ）。ファイルのログはそのまま

### 11.8 commit

```bash
python -m app.cli commit --job 3
python -m app.cli commit --job 3 --wait 60 --json
```

| オプション | 説明 | デフォルト |
|-----------|------|-----------|
| `--job ID` | 送信キューの ID（必須。状態が送信完了の件だけ） | — |
| `--wait SECONDS` | 結果を待つ秒（1 以上） | 送り先の `commitment_timeout_seconds` |

- 送り先が保管確認を使わない（`storage_commitment: false`）なら、送らずに
  終了コード 2 で止める
- 待ち受け（`modality.listen`）を立ててから N-ACTION を送り、結果か `--wait` の
  秒まで待つ。待ち受けを立てられない（ポートが使われている）ときは、送らずに
  終了コード 2 で止め、画面が動いていないかを確かめるように出す
- 結果が確認済なら終了コード 0。確認の失敗、または `--wait` の間に来ない（状態は
  確認待ちのまま。時間切れはキューが決める）なら終了コード 5
- 出力は件の ID・状態・確かめた画像数／求めた画像数。`--json` では `job_id`・
  `transaction_uid`・`status`・`num_requested`・`num_confirmed`・`num_failed`・
  `error`

### 11.9 mpps

```bash
python -m app.cli mpps list
python -m app.cli mpps list --json
python -m app.cli mpps retry
```

- `mpps list`：MPPS の通知のキューを出す（ID・MPPS の状態 `IN PROGRESS`・
  `COMPLETED`・`DISCONTINUED`・送れたか・受付番号・時刻・失敗の理由）。`--json`
  で JSON
- `mpps retry`：送れていない通知を、古い順に送り直す（8.4.1）。MPPS を使わない
  設定で、送れていない通知も無いなら終了コード 2。送れない分が残れば終了コード 5
